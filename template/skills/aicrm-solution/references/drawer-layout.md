# 侧滑窗口布局规范

适用于本项目及衍生模板中的所有侧滑窗口（Drawer/抽屉），包括管理中心、工作台、插件的新增、编辑、详情及授权窗口。新增或修改相关窗口时必须遵循；本次规范落地不代表历史窗口已完成迁移，也不授权批量改写业务页面。

## 固定 Header

- 每个侧滑窗口必须有独立 Header，固定在窗口顶部，不能随正文滚动或移出可视区域。
- 存在主窗口 Header 时，业务抽屉的根容器、遮罩及内容区域须统一避让主 Header，使用宿主实际 Header 高度与可用视口边界；不能让抽屉标题栏落到主 Header 后方。同步限制底部边界，避免只增加 top 偏移后仍保留全视口高度。内联、嵌套或特殊全屏抽屉按实际挂载容器计算，避免重复偏移。
- 标题位于 Header 左侧并左对齐；不能居中或放入滚动正文。
- 保存、提交、确认、取消等窗口级操作统一置于 Header 右侧并右对齐，主操作放在操作组右侧。没有保存动作的详情窗口不人为增加保存按钮。
- 关闭入口保留在 Header，沿用组件已有的关闭方式，不重复生成关闭按钮。操作组与标题、关闭入口不能互相遮挡。
- 不在底部 footer、滚动正文末尾或悬浮底栏重复放置同一组窗口级操作。正文中的行操作、增删子项等局部操作仍保留在对应内容区域。

## 滚动与实现

- Header 和正文采用分离布局：外层限制为侧滑窗口可用高度，Header 不收缩，正文占剩余空间并独立滚动（通常为 `flex: 1; min-height: 0; overflow: auto`）。不要让整个 Drawer 容器滚动。
- 使用 Ant Design Drawer 时优先复用原生 `title`、`extra` 和关闭入口，将窗口级操作放入 `extra`；移除原 footer 操作，确保 body 为滚动区域。自定义抽屉也必须兑现同样的结构。
- 窄窗口、长标题或多个操作时，允许标题省略并提供完整标题提示，或让 Header 自适应增高；不能把操作挤到窗口外，也不能通过把操作移到底部来适配。
- 沿用现有主题、间距和按钮风格；深浅主题都需可辨识。不为应用规范改动字段、权限、保存接口、校验、取消或关闭语义。
- 若 Header 按钮位于表单 DOM 外，通过表单实例或明确的表单关联触发原提交链路；不能绕过校验。保持保存 loading、防重复提交、权限控制及未保存提醒。

## 验收

1. 正文滚动到顶部、中部和底部时，Header、标题及操作按钮始终可见且位置稳定。
   同时确认抽屉顶边位于主 Header 下方，标题和操作无覆盖，底部在可用视口内；遮罩与内容边界一致。
2. 标题在 Header 左侧，保存等操作在 Header 右侧；底部无重复的窗口级操作栏。
3. 窄窗口、长标题、多操作及深浅主题下不遮挡、不溢出，正文可完整滚动。
4. Header 保存仍触发原表单校验，提交中状态正常；取消、关闭、权限过滤行为保持原语义。
5. 报告实际迁移范围；对界面改动进行真实窗口核验，构建通过不能替代布局与滚动验收。
