## 3. 已确认缺陷与审查清单

### F01 B 的多角色数据范围误拒绝

优先级：P2；状态：已在本地迭代分支修复；回归测试先复现失败，修复后通过。尚未合入 main 或部署。

位置：[统计权限判断](https://gitea.jditco.ltd/kysion/kycrm/src/commit/f096b35d6c5135295f9decb2f6a431dc55dee113/services/ky-org-service/internal/server/agency_statistics.go#L69)。贡献原始代码遇到任意非 `all` 范围即返回 403；本地迭代修复见实施记录。

复现条件：同一平台成员具有所需查看权限，角色一授予 `all`，角色二授予 `specified_enterprise`。Membership 返回两条有效数据范围；统计接口却拒绝请求。最小 handler 复现期望 200，实际 403。

修复目标：遵循项目已有的角色范围并集语义。通过可信 actor/session/workspace/membership 和所需权限校验后，只要有效范围包含 `all`，本批全量统计即可放行；仅有受限范围、空范围或无权请求继续拒绝。本轮不因此新增部分范围统计，也不能让客户端声明 `all`。

必须新增的回归：

| 数据范围或条件 | 期望 |
| --- | --- |
| 仅 `all` | 允许 |
| `all` + `specified_enterprise` | 允许 |
| `all` + `specified_agency` | 允许 |
| 只有指定机构/企业范围 | 403，不返回零值冒充成功 |
| 无范围、缺权限、错误成员或工作区 | 拒绝 |
| 权限决策服务超时或不可用 | 503，不扩大权限 |

### F02 其他项为待核验风险，不作为已确认缺陷

- A：慢保存期间再次输入、冲突后重载、后台 refetch 和工作区切换时，输入、版本与缓存是否保持一致。
- A：旧写入口与新条件写入口混用时，版本失效语义是否与文档一致；不能宣称旧客户端也获得完整 CAS 保护。
- B：100 组、5000 映射、1000 用户分块及 5 秒预算的实际边界；超限不能截断成看似精确的数字。
- C：草稿素材泄漏、跨机构素材引用、平台继承刷新、慢响应串工作区、权限撤销及失败回退。
- D：Host/代理头伪造、源站绕过、DNS 重绑定、签名重放、任务晚到结果、域名所有权丢失和跨入口会话使用。

后续审查只把具备代码位置、触发条件及复现证据的问题升级为缺陷；不以猜测宣称漏洞已经存在。

## 4. 各批功能与验收要求

### A 平台版权与版本条件编辑

保留平台主体可空的既有语义，增加 `standard/full/chinese` 三种版权风格；平台主体为空时沿用已有品牌回退，不填入真实公司默认值。年份与跨年时区展示保持一致。

- GET `/api/v1/platform/platform-profile` 返回风格及字符串 `revision`。
- 新 PATCH `/api/v1/platform/platform-profile/edit` 使用 `{expectedRevision, fields}`，沿用 `platform.basic_info.update`。
- 字段省略表示保留、文本空串表示清空；null、未知字段和非法枚举拒绝。
- 无版本 428、冲突 409；冲突不自动丢弃当前表单，仅经用户确认加载最新配置。
- 新条件写、版本推进与字段名审计同事务；审计失败必须回滚。
- 原 PATCH 保持兼容并推进版本，但仍有旧覆盖语义。若未来废弃，另行制定客户端兼容计划。

验收：两个编辑窗口竞争更新、旧写使新编辑版本失效、审计失败回滚、保存失败保留输入、保存期间新输入、后台刷新、空主体、三种风格、跨年、亮暗主题及窄屏。平台 Header、浏览器标题和登录页的消费结果一致。

### B 机构企业统计与活动状态

机构显示旗下企业数量；机构和企业显示用户在线、在职、离职、累计数。终端明确显示“未接入”，不得出现伪造的终端数量。

- 统计入口：POST `/api/v1/platform/agencies/statistics`、`/api/v1/platform/enterprises/statistics`，每次 1—100 个唯一 ID。
- Org 拥有机构/企业事实，Membership 拥有成员事实，Auth 拥有账号/会话事实，通过内部接口组合，不跨服务查询私表。
- 成员按账号去重，active/disabled 在职优先于 left，invited 不计入；仅有效 active 身份可在线。
- 在线为近期活动指标：账号正常、会话有效且 90 秒内有心跳，不是实时连接数。
- Host 在页面可见且存在会话时每 30 秒上报；失败不清理正常登录态。
- 缓存隔离 actor、工作区、成员身份、列表范围及 ID；登出、身份撤销和工作区切换不得展示旧范围数字。
- 列表先显示，统计异步加载；悬浮、聚焦、点击详情可刷新；失败显示不可用与重试，不显示假零值。

验收：修复 F01；去重与在职优先、邀请排除、禁用/删除账号、撤销/过期会话、过期心跳、跨机构隔离、映射预算、依赖故障、慢请求切换及真实规模性能。若未达到规模验收，只能发布已确认规模，不承诺无限量统计。

### C 机构品牌发布与继承

复用贡献中的品牌草稿、素材、快照和 Host 消费链路，保持平台与机构配置分层。

- 字段级平台继承与机构覆盖分开；清空覆盖值恢复继承，不把平台值复制成机构私有值。
- 支持品牌名、应用显示名称、独立图标文字、PNG 应用图标、透明文字 LOGO、版权主体与风格。
- 上传素材与机构归属绑定，执行 4MB/像素预算、格式解码与归一化；草稿预览鉴权、不缓存。
- 草稿保存使用版本条件；发布生成不可变快照；回滚产生新版本，不修改历史快照。
- 工作区品牌由服务端确认的当前工作区决定，企业按其机构关系获取继承结果，不接受客户端随意指定机构。
- 平台配置变化会更新继承后的有效指纹；切换工作区或失败时不得短暂显示上一机构品牌。
- 公开素材只提供符合发布及机构状态要求的资产。历史公开素材不是保密附件，需在产品说明中明确这一边界。
- `view/update/publish` 分权，注册权限不自动授予所有角色。

界面遵循项目 Drawer 规范：固定 Header、左侧标题、右侧保存/发布操作，仅正文滚动；避让主 Header 和状态栏。验证宽窄窗口、亮暗主题、慢响应、图片失败及取消/关闭语义。

范围不包括安装包、原生签名、桌面图标更名、商业品牌或客户端分发。机构公开登录页的入口识别由 D 完成，C 不通过 URL 参数猜测机构。

### D 托管域名与入口登录隔离

该批先做完整代码及架构审查，再验证外部基础设施，不直接启用现有草稿。

- 域名绑定需具备候选/活动生命周期、验证、激活、暂停、恢复、解绑、取消及挑战更新。
- TXT 自动处理仅限明确授权的账号、Zone 和记录；NS 变更提供准确指引，不能把“已展示指引”当作 NS 已完成。
- 域名操作具有持久化任务、租约、幂等键、revision、晚到结果抑制、所有权复核和可归属记录清理。
- 只有 Worker 持有受限 CF 凭据；业务服务、Host、浏览器和构建 Job 不持有这些凭据。
- 候选/未知 Host 不能建立业务会话；专用探针采用短期、绑定 Host 的签名，不复用内部服务凭据。
- 会话绑定可信入口 host、binding 和 generation；bootstrap 只返回该入口允许的身份，每次业务请求重新验证。
- 错误密码与非旗下账号使用一致的拒绝响应；明确入口失效与依赖 503 分开，后者不随意清理会话。
- 网关阻断内部路由及伪造代理头，必须验证无法绕过网关直连源站。
- 公网验证固定 HTTPS 443，检查实际连接 IP、拒绝跳转，防止 SSRF 与 DNS 重绑定。
- 统一 Host 的大小写、端口、末尾点与 IDNA 规范化；对重复/畸形 Host、伪造入口头、越级子域和未授权根域做负向验收。当前贡献不开放 IP 映射，不借验收扩大入口类型。
- 任务重试、限流、CF 错误分类与补偿清理需有预算和审计；不把密钥、原始凭据或可复用签名写入页面、日志或仓库。

当前贡献明确不支持 WebSocket/Upgrade；REST、上传下载和 SSE 受 30 秒网关限制。需实际测试下载、上传及 SSE 重连，不把它描述成平台长连接等价方案。若业务要求更长传输，先修改合同与资源控制，再开放。

## 5. D 与当前 K3s 架构的前置决策

当前首期部署合同是 Web 与五个普通服务，Executor 延后；业务服务通过 ClusterIP 通信。D 的样例使用六服务门禁、业务回环监听、systemd Worker/Gateway 和专用 Tunnel，不能原样应用到现有 Pod。

实施 D 前需完成下列设计并确认：

1. 明确 Gateway、Worker、服务门禁与现有 Web/Ingress 的边界，逐个列出外部与内部请求路径。
2. 本项目优先完成 Kubernetes 适配，继续沿用现有集中构建与 K3s 发布体系；原生 systemd 样例仅作参考。若确需另设原生组件，必须另写架构决策，说明运维、身份、数据所有权与回滚成本，不能直接作为等价部署选项。
3. Kubernetes 适配若需要服务间网络监听，先设计等价的可信入口上下文、服务身份与网络约束，并完成负向测试。不得直接删除 loopback 校验、放宽为任意监听或关闭隔离门禁。
4. 明确未部署 Executor 时的能力与门禁合同；不能伪造其健康状态，也不能为通过域名验收擅自部署 Executor 或静默剔除第六门禁。
5. 确定专用 Tunnel、可信 Host 精确白名单、源站访问控制与探针路径；禁止通配转发暴露其他运维入口。
6. CF/DNS/NS/证书与新公网入口操作需有明确资源范围授权。本方案不授权修改真实 DNS/NS，也不自动扩大现有部署授权。

当前 D 仍保持 WIP 和默认关闭，不能因本次复评直接认定可合入。后续区分两个门槛：代码接纳要求完整审查、准确 SHA 检查、默认关闭回归和迁移兼容通过；功能启用还要求部署合同、真实外部资源与安全验收通过。若选择先接纳默认关闭代码，可在第一门槛满足后申请移除 WIP，不以先修改真实 DNS 为必要条件。C 可先提供已认证工作区品牌，不因 D 未上线而阻塞 A/B/C 的独立交付。

已核实的适配限制：`shared/domainentry/entry.go` 的 `Validate` 在入口开关为空或 `0` 时直接通过，`Wrap` 在关闭时不执行入口隔离；但新增 capabilities 路径返回 503，不能据此概括为完全零差异。Org 等服务在入口开关为 `1` 时强制 `LoopbackListen`；内部 `Call` 仅接受 HTTPS 或回环 HTTP，现有 ClusterIP HTTP 地址也不能直接复用。K3s 适配需同时解决监听、服务间传输和可信入口边界，不能只修改一个监听参数。关闭开关的源码证据不等于整批功能无影响，仍需验证新增路由、迁移和旧客户端。

## 6. API 与部署接线核查

每批输出“路由—服务—权限—代理—测试”的核对表，包含公开读取、受权读取、写操作与内部接口；不能只检查 handler 已注册。

| 范围 | 必查内容 |
| --- | --- |
| A | 新 `/platform/platform-profile/edit` 由现有受控前缀正确代理；请求版本和错误码端到端保留 |
| B | 两个统计 POST 和 `/auth/presence` 可达；内部统计与 access-decisions 仍不公开；Org 使用受控 Membership/Auth 地址 |
| C | agencies branding、current branding 与公开 `public/brand-assets` 的完整接线；当前未知 API 的 404 策略不能误拦合法新路径，也不能因此开放整个内部前缀 |
| D | domains、domain-summaries、public entry、签名探针、受权业务转发分别列出；校验 TLS/Host/代理头、超时、请求体与缓存策略 |

新增静态资源或公开素材接口必须检查类型、大小、缓存、撤销语义及跨机构归属。上传体积要按 base64/JSON 实际大小验证，不能只比较原始 PNG 大小。

本项目复用现有 GitHub 集中构建及 digest 发布方式；域名 Worker/Gateway 的新增镜像、探针、资源限制和最小权限是 D 的新增交付物，不假设现有工作流已经构建它们。

- 编号与名称来自当前贡献基线，实施前检查是否被其他已合入迁移占用；冲突时调整未发布的新迁移，不能改动已执行迁移的校验和。

- 新空独立测试库与从当前结构升级的独立副本分别验证。集成测试必须有专用库名与连接保护，禁止向准生产数据库注入测试表或失败触发器。
- 迁移身份执行 DDL；按领域表所有权补最小运行权限。当前环境既有共享 schema/运行身份边界需单列核对，不能只添加一份 role 示例就声称隔离已兑现，也不借本轮静默重构全部数据库身份。
- 新权限先注册，按管理员确认给目标角色授权；无授权角色不得因前端菜单可见而获得能力。
- 核验事务审计失败回滚、重复迁移、缺失权限、升级顺序及旧二进制兼容窗口。
- 发布前保存数据库备份、迁移账本、旧配置及镜像 digest。备份完整性检查与实际恢复演练分开记录。

## 10. 合入与发布流程

1. 在隔离分支处理修复；不在当前准生产运行目录直接修改业务代码。
2. 合入前再次确认 head 未变化；变化后重新检查差异、测试及批准有效性。
3. 先完成准确 SHA 上的检查和独立评审，再由集成者执行明确获准的合并；无文本冲突不是批准依据。
4. A 合入后调整 C 的 base 并排除重复前置提交；C 合入后同样调整 D。B 仅处理自身与新主分支的差异。
5. 对最终合并结果重新执行相关前端构建/typecheck、Go、Shared、迁移和代理集成检查，更新 API、权限、模板说明及 CHANGELOG。
6. 通过 GitHub 集中构建发布私有镜像，锁定完整 source SHA、workflow 版本、run、artifact 和 image digest；构建 Job 不持有运行凭据。
7. 发布前备份，受控执行迁移和运行权限调整，再更新服务与页面；Argo 同步后检查探针及真实业务路径。
8. 每批在准生产环境单独验收，不把 C/D 暗中随 A/B 开启。自动发布链路本身仍是独立待接入事项，不能在本轮合并时顺带开启。
9. 记录准确的已合入、已部署、已验收和未完成项，分别关闭对应任务；不依据未完成的草稿统一结项。

## 11. 回滚与停用

| 批次 | 应用回滚 | 数据与安全边界 |
| --- | --- | --- |
| A | 使用已验证的前一镜像与配置 | 保留新增风格/版本/变更表；旧二进制不再提供完整条件写保证 |
| B | 停止新心跳与统计消费者，回退服务/页面兼容版本 | 保留心跳列和索引；不删除原会话或伪造历史心跳 |

数据库不随镜像自动降级；恢复备份可能丢失备份后的业务数据，必须单独评估和授权。域名绑定解除不等于撤销所有历史副作用，需复核会话失效、任务晚到结果、记录归属及资源清理。回滚方案应在独立环境演练，不直接对准生产执行破坏性验证。
