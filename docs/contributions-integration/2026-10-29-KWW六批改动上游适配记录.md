# KWW 六批改动上游适配记录

## 目标与边界

本记录说明从 KWW 源仓库六批迭代中筛出的通用贡献如何适配到 kycrm。目标分支从 `origin/main` 基线 `0e4734009cab700a4dd8bd5aa2924597c3c81767` 开始；KWW 源仓库及其历史未修改。本分支不合并、不部署、不执行数据库迁移，也不安装、构建或运行 Electron。

目标仓库与 KWW 在共同祖先 `a9d1269f24b3ca4a97f87a78f62bb5c89ca7a740` 后已独立演进。六个源提交不是可直接 cherry-pick 的提交序列；本分支只移植有目标侧依赖基础且不改变目标产品身份、权限边界和 UI 合同的最小独立改进。

## 本次实现

### 桌面启动离线恢复

- 新增 `apps/aicrm-desktop/src/main/desktop-startup-navigation.ts`，以明确状态管理 loading、ready、offline、disposed；只记录目标 host、错误码和事件名，不记录完整 URL 或查询参数。
- `app-window.ts` 将控制器绑定到主 BrowserWindow 的加载、失败、显示和销毁事件。离线页继续使用目标仓库已有 `kww-offline://local/` 与角色授权路径。
- `app-menu.ts` 将“重试后台连接”放入常规“视图”菜单，并调用当前主窗口控制器重试；不再依赖插件宿主是否启用，也不通过可能聚焦到其他窗口的 BrowserWindow 重新加载。
- 此处只完成控制器行为测试与源码接线检查；未安装或运行 Electron，真实窗口启动/重连仍需在目标客户端环境验收。

### 角色授权回显

- `services/ky-membership-service/internal/store/role_store.go` 先按既有 workspace 条件分页查询角色，再仅用该页角色 ID 批量读取 `ky_role_permission`，并稳定排序后填充 `PermissionIDs`。
- 系统模板角色与当前工作区角色都按现有查询返回；数据库表、授权写入接口和权限判定没有变化。SQL 参数使用占位符，未增加迁移。
- `role_store_permissions_test.go` 覆盖角色分组、空权限列表和忽略不在当前页角色集合中的数据。

## 数据库与安全边界

源迁移 `ops/db/123_menu_webview_common_config.sql` 与 `ops/db/124_orphan_agency_enterprises_menu_permission.sql` 均未带入：目标仓库当前迁移目录止于 106，且缺少这些迁移依赖的业务表与菜单权限模型。没有数据库迁移文件，也没有执行迁移或数据库写入。

未引入 KWW 域名、应用 ID、Nginx 规则、生产操作记录、脚本源码、代理凭据或客户数据。没有改目标部署配置、运行服务或远端分支。
