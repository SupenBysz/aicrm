## 接线与数据所有者核对

| 功能路径 | 所有者 | 访问约束 / 部署接线 |
| --- | --- | --- |
| `/api/v1/platform/platform-profile/edit` | Org | 既有 profile 代理前缀覆盖；平台更新权限及 expectedRevision |
| `/api/v1/platform/{agencies,enterprises}/statistics` | Org | 既有列表前缀覆盖；可信成员/权限/完整数据范围，再调用 Membership 和 Auth |
| `/api/v1/auth/presence` | Auth | 既有 auth 代理前缀覆盖；有效会话 |
| `/api/v1/platform/agencies/{id}/branding/*` | Org | 既有 agencies 代理覆盖；view/update/publish 分权，素材机构归属及版本条件 |
| `/api/v1/organizations/current/branding` | Org | 既有 organizations 代理覆盖；服务端确认当前工作区 |
| `/api/v1/public/brand-assets/{assetId}` | Org | 新增明确代理；仅已发布且机构有效素材，草稿不可公开 |

## 浏览器验收

使用本地编译后的 Host、真实 Auth/Org/Membership、独立数据库与临时本地代理完成：

1. 测试账号登录和管理中心机构列表；统计数字可读取，终端显示未接入。
2. 机构品牌名称、应用名称和图标文字输入，自动生成素材及保存草稿。
3. 发布生成版本 1，刷新重新打开仍读取该版本。
4. 修复素材字段监听后，重新打开可看到浅色与深色图片预览。
5. 暗色主题、150% 缩放及正文滚动观察；发现 Header 占用宿主顶栏区域后补专用边界样式。浏览器随后被用户切换且工具超时，最终边界样式的视觉复验尚未完成，不能记为通过。

测试结束已停止自行创建的本地服务、HTTP 代理与 PostgreSQL；未关闭用户浏览器或其他应用。

本地 HTTP 代理按仓库 Nginx 路由所有者转发，证明 API 接线与真实服务合同；没有运行 Nginx 二进制，因此不替代 Nginx 配置加载和 K3s 验收。也未验证当前已安装 Electron 客户端。

## D 批下一阶段约束

当前源码仍强制回环监听，且内部普通 HTTP 只允许回环地址；现有 K3s ClusterIP HTTP 不能直接开启。新增 `ops/container/domain.Dockerfile` 仅支持 domain-worker/domain-gateway 两个明确命令，复用已锁定基础镜像；未把组件或凭据加入默认工作负载。

后续按需求方案第 5 节完成 K3s 适配和源站防绕过合同，保留可信入口、服务身份及网络约束。Executor 尚未部署时，六服务门禁必须失败；不能靠跳过 Executor、伪造健康或放宽监听解决。真实 CF 资源及测试域名范围确定并通过对应验收后，才进入启用阶段。
