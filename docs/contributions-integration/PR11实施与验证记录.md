## 3. 数据及兼容要求

1. 107保持原文件及SHA-256；因其自带BEGIN/COMMIT，台账执行器仅对该精确校验和去掉外层包装，并在台账事务内执行，修改后的107仍被拒绝。
2. 108新增`permission_bindings`、`source_version`和目录基线；109新增作用域修订及事件表。二者由台账执行器拥有事务，不能单独手工执行替代台账。
3. 老Host不具备作用域修订参数时，新增写合同返回428，不能自动补最新修订号。旧标签页需刷新；新Host与匹配Desktop分别发布。
4. 原生状态协议为v2；新增宿主浮层有独立preload和本地UI包。Web发布不更新安装客户端。
5. `generate_menu_catalog.mjs --check`检测插件注册与可信清单漂移。后续清单升级必须追加迁移，不重新生成或重写已发布108。
6. 当前历史数据库/模块引用尚未现场全量核对；不能把“初始化不会覆盖”误解为历史数据已经清理。

## 4. 文件存储合同

客户端`userData/local-credentials-v1`为新命名空间。主进程持有随机32字节文件密钥，使用AES-256-GCM；目录0700、文件0600，拒绝不安全文件、符号链接及篡改密文。没有明文后端或系统钥匙串回退，密钥不进入renderer、IPC或仓库。

此方式依赖当前用户私有目录的文件访问控制；同时取得文件密钥和密文的主体可以解密，不将其宣传为系统硬件密钥保护。Windows文件ACL尚需Windows环境验证。

旧OS加密文件保持原路径和原内容，不读取、不自动解密迁移。若宿主仍有有效Web会话，通过正常会话同步写入新目录；只有旧钥匙串会话而没有可用Web会话时，需要重新登录。旧设备/授权记录不会自动复制到新命名空间，必要时按正常流程重新授权。回退客户端也必须遵守不主动调用钥匙串的要求。
