# 品牌 LOGO 与 AI 图标适配规范

适用范围：KyCRM Host、Core、系统配置、个人偏好、组件中心，以及从本基座派生的新项目。本轮只修改 KyCRM，不修改或部署直聘AI等派生项目。截图只能说明需要核对的现象，不能据此宣称其他项目的源码、配置或部署已修复。

本专题与 [产品交互设计总则及验收入口](../design/README.md) 共同执行；品牌一致性不能替代页面作用域、任务流程、状态反馈和可访问性设计。

## 唯一组合规则

完整 Logo = 当前生效的品牌文字图片 + 可选的共享矢量 AI 后缀。后缀包含分隔圆点与 AI 图形，统一由 `BrandAISuffix` 绘制，使用当前主题强调色，有效图形高度为品牌有效高度的 92%。

- 页面优先使用 `BrandLogo`，其内部复用 `BrandLogoLockup` 与 `BrandAISuffix`；不复制 SVG path、不使用普通字体的 `AI` 模拟图标，不直接拼接 `name + "AI"`、`name + "·AI"`。
- `BrandLogoLockup` 是底层组合/测量组件，供自定义布局和品牌设置中的素材预览使用；并非要求每个业务页面重新实现 Logo 的加载和降级逻辑。
- `brand.name` 是品牌文字，如“示例”；`applicationName` 可以是“示例AI”等完整应用显示名称。窗口标题与品牌图形是不同用途，不得把完整应用名称直接当作“文字 + AI图形”再重复拼接。
- 用户上传的亮/暗文字 Logo 仅包含品牌文字，PNG 透明，不应把圆点或 AI 后缀烘焙进图片。已上传合成图必须人工重新制作，代码不能可靠识别或删除其中的 AI 图形。
- 不得自动正则剥离品牌名称中的 `AI`，因为它可能是合法名称的一部分。迁移时先核对实际字段与图片内容，再由操作者配置品牌文字、应用名称和显示开关。

## 开关与素材

`showAiIcon === true` 才显示共享 AI 图标；false 或缺失时隐藏。关闭开关后预览没有 AI 是正确行为，不得为了让截图“看起来一致”强制打开开关。单独修改 `applicationName` 不应改变开关。

| 配置 | 亮色使用 | 暗色使用 |
|---|---|---|
| 平台品牌 | `wordmarkId` 对应公开素材 | `wordmarkDarkId` 对应公开素材 |
| 机构/工作区有效品牌 | `wordmark.url` | `wordmarkDark.url` |
| 缺少素材或图片加载失败 | 当前品牌名称生成的亮色透明文字图；再失败回退文字 | 当前品牌名称生成的暗色透明文字图；再失败回退文字 |

上传图片不强制反色，不在暗色中复用黑色图片。既有资产和开关保持不变，本次不自动改写用户品牌数据。

## 完整 Logo 在各入口的使用

| 入口 | 品牌来源 | 要求 |
|---|---|---|
| 顶部展开导航 | Host 解析的当前工作区有效品牌 | 使用 `BrandLogo`；收起导航仍使用图标文字/短名，不强行加入 AI |
| 登录页 | 机构入口品牌或平台品牌 | 使用相同组合组件，不自行追加普通字体 `AI` 或 `Console` |
| 平台外观、个人偏好主题卡片 | `BrandIdentityProvider` 注入的当前有效品牌 | 每张卡片按该候选主题的亮/暗色变量显示两组完整 Logo；不得写死 Kysion、KyCRM、客户名称或只显示 Aa |
| 品牌配置中的应用 Logo 预览 | 当前表单草稿 | 使用亮暗对应素材及草稿开关，不读取已保存值来覆盖草稿 |
| 组件中心独立示例 | 显式提供的虚构 `BrandIdentity` | 不发业务请求，不读取实际用户品牌；缺少上下文时显示“品牌 Logo 未配置”，不能伪装成正式客户 Logo |

主题卡片应复用正式 Logo 的图片、图标、间距和宽高比，不是把正式图替换为近似字体。图片本身保留上传颜色；AI 后缀使用候选主题强调色。卡片不显示重复的“亮色/暗色”文字标签，但保留可访问名称。

## 数据流与模块边界

- Core 公开 `BrandIdentity`、`BrandIdentityProvider`、`useBrandIdentity` 和 `BrandLogo`，只负责表现，不获取平台/机构 API、会话或权限数据。
- Host 的 `PlatformProfileProvider` 注入平台品牌；工作区内由 `WorkspaceBrandProvider` 注入当前有效品牌，供导航及插件共用。切换工作区时先清除旧身份的可见品牌，不能短暂显示上一个机构的品牌。
- `AppearanceControls` 默认读取上述上下文；独立演示/嵌入场景可通过 `brand` 属性显式注入。业务插件不得为预览另行维护一套品牌默认值。
- 平台品牌更新、机构品牌更新后复用既有刷新事件重新加载。不要用截图或 CSS 覆盖旧名称来掩盖错误数据源。

```tsx
import { BrandIdentityProvider, AppearanceControls, BrandLogo } from "@ky/admin-core";
const brand = {
  name: "示例",
  applicationName: "示例AI",
  wordmark: { url: "/example/light.png" },
  wordmarkDark: { url: "/example/dark.png" },
  showAiIcon: true,
};
// 以下 URL 仅作说明，不是可直接调用的项目接口。
<BrandIdentityProvider brand={brand}>
  <BrandLogo brand={brand} dark={false} maxHeight={40} />
  <AppearanceControls themeId="classic-gold" mode="light" onChange={() => {}} />
</BrandIdentityProvider>;
```

## 尺寸与验收

1. 优先遵守最大高度，再按可用宽度等比缩小；不得因容器变宽而把 Logo 无限放大，也不得横向拉伸。
2. AI/圆点占用空间纳入总宽度。顶部品牌区保留既有左右最小 16px 容器规范，不盖住工作区切换控件。
3. 上传图按实际透明图形高度测量；无图片文字降级同样受 `maxHeight` 限制。
4. 覆盖四套主题 × 亮/暗、不同品牌、开关开/关、缺失暗色图、图片失败、长名称，以及窄/宽容器。
5. 品牌信息、主题缩略图、顶部导航和登录页应分别核对同一份身份数据。以浏览器实际结果验收；编译成功不能替代视觉验收。

## 派生项目适配清单

- 同步 Core 的品牌组合组件、上下文与导出；同步 Host 的平台/工作区注入、导航和登录接入；同步外观选择及组件中心示例。
- 同步对应 CSS、组件索引和本规范，不能只复制某个 JSX 或 SVG 文件。
- 检索并人工确认硬编码 Kysion/KyCRM、`name + "AI"`、静态主题缩略图和普通字体 AI 后缀；合法应用名称、说明文案不应全局替换。
- 配置新项目名称和两套透明文字图片，核对 AI 开关。保留已有配置、机构隔离、授权和发布历史。
- 完成上方验收矩阵后独立提交、构建、部署和复验；KyCRM 修复不会自动更新其他项目，不得混用源码完成、构建完成、已部署和已验收的状态。
