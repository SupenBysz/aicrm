## 功能与责任

| 模块 | 已提取的参考能力 |
| --- | --- |
| Web专用窗口 | 独立shell和业务WebContentsView、固定preload、窗口复用/隔离、槽位布局、尺寸与关闭清理、同窗口导航及外部协议处理 |
| 导航与状态 | 导航代次、页面事件、SPA路由、窗口计数、全局锁定、窗口/任务栏标题与状态投影 |
| 脚本消费 | 资源声明、版本策略、服务端resolve/manifest、JS/CSS顺序、幂等、来源约束、超时、缓存、document-start预注册和紧急停用 |
| JSSDK | lifecycle、net、public、host/store、window、ui；公共模块注册、宿主上下文查询、标题、最多4个动作按钮、受控UI通知/确认 |
| 网络 | CDP观察/等待、来源和能力约束、敏感头脱敏、正文大小限制、导航/销毁时回收；拦截需显式获批能力 |
| 窗口插件 | 独立隐藏插件BrowserWindow、专用preload和sender校验、声明式投影、固定导航动作、状态栏/版本面板；不授予任意IPC或业务权限 |
| 插件升级 | 专用插件ID/签名域、Ed25519校验、policy/index/package摘要、序号高水位、吊销、候选、试运行、稳定提交及失败回退 |
| 构建与发布工具 | 五个preload独立打包、签名工具的密钥权限/公私钥一致性检查、发布前验签和文件替换、固定槽位与分发测试 |

插件属于桌面宿主插件体系，不注册为AdminPlugin。Electron拥有原生窗口、隔离和能力授权，后台插件仍通过Host/Core的DesktopPort调用；业务权限和工作区事实由服务端负责。JSSDK浏览器fallback与桌面宿主能力存在差异，缺失能力必须明确拒绝。

## 当前项目适配

1. `KY_WEB_WINDOW_PLUGIN_SOURCE`取代参考写死的远程插件地址；默认空值，宿主关闭远程检查，只使用内置插件。显式配置前应使用当前项目自己的受信公钥和发布通道。插件ID及签名域保留来源协议，避免随意改名破坏包校验。
2. 发布脚本必须配置`KY_WEB_WINDOW_PLUGIN_DEPLOY_ROOT`，没有参考生产目录默认值，也不输出参考发布域名。此次没有执行签名或发布，没有携带私钥。
3. 桌面新增React/ReactDOM/Antd依赖沿用当前Host版本；锁文件同步桌面依赖，不升级整个工作空间的UI库。
4. 修正一个已证实的参考过时测试：公共API已内联到`web-window.ts`，不再读取被删除的`public-script-api.ts`。UI合同测试改为检查桌面与Host依赖一致，保持版本适配的可验证性。
5. 带入原JSSDK接口参考文档，保证代码补全、preload和合同测试使用同一技术文档；不复制阶段性部署记录、客户数据或实际运行日志。

参考专用公钥文件是公开验证材料，不是私钥。默认关闭远程更新并不替代发布时的信任配置；独立项目发布前应更换自己的公钥，保持manifest、policy、index和包签名一致。当前包未重新签名，也没有发布可下载产物。

## 应用与构建

在相应基线根目录依次检查、应用01→02→03；每一步成功后再执行下一步。第四份保持为参考。

```bash
git apply --check docs/web-window-upgrade/patches/01-web-window-foundation.patch
git apply docs/web-window-upgrade/patches/01-web-window-foundation.patch
git apply --check docs/web-window-upgrade/patches/02-web-window-plugin.patch
git apply docs/web-window-upgrade/patches/02-web-window-plugin.patch
git apply --check docs/web-window-upgrade/patches/03-desktop-host-integration.patch
git apply docs/web-window-upgrade/patches/03-desktop-host-integration.patch
corepack pnpm install --frozen-lockfile --ignore-scripts
corepack pnpm --filter @ky/admin-core build
corepack pnpm --filter @ky/aicrm-desktop typecheck
corepack pnpm --filter @ky/aicrm-desktop build
corepack pnpm --filter @ky/plugin-matrix-account typecheck
corepack pnpm --filter @ky/plugin-script-management build
corepack pnpm --filter @ky/admin-host typecheck
```

Node单元测试需加载项目的Electron替身：`node --import ./scripts/desktop-plugins/test-loader.mjs --test <测试文件>`。`*.electron.test.mjs`需真实Electron执行，不能使用Node命令替代真实客户端验收。完整已运行文件集合写在manifest中。

## 验证与限制

隔离副本中，前三份组合完成桌面typecheck/build，五个preload独立打包且不含本地require分块；Core build、矩阵账号插件及Host typecheck通过。窗口、导航、网络、SDK、运行时及分发等Node测试101项通过；其中店铺消费交叉合同使用第四份参考文件作为源码夹具，并未宣称店铺模块已经迁入。

第四份是非独立的店铺参考源码。试将它放入当前Host的插件扫描范围，会暴露参考店铺页面本身的TypeScript语法错误，且缺少完整店铺模块与后端依赖；因此不作为可直接合入补丁验收，不修复或迁入无关店铺业务来掩盖问题。

未完成真实Electron窗口打开、登录态、跨导航document-start、Windows/macOS实际插件升级、真实网络拦截、店铺API、云同步和签名发布验证。编译与Node替身测试不能证明这些结果。宿主接线包含参考的登录空间能力，当前缺少对应后台服务时应保持入口不启用或安全拒绝。

## 发布与回滚

先审阅前三份差异及外围业务依赖，再应用源码、冻结依赖、构建和本地夹具验收。接入对应业务入口后完成真实窗口验收；仅在明确当前项目发布源、信任公钥和发布目录后执行插件发布。

未发布时按03→02→01反向撤销。已发布时保留当前插件状态和包缓存，利用参考的稳定包回退/紧急停用能力；回退桌面产物时检查缓存协议兼容性，不删除登录空间数据或无关插件目录。
