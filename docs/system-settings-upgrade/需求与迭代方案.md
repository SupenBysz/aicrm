## 3. 逐项需求与验收

### U01 系统配置入口、导航与公共体验

1. 继续复用 `plugins/ky-system-settings`，菜单名“系统配置”、路径 `/system`；实际 Host 以 `/w/{type}/{id}/system` 承载。菜单 key 保留 `system.settings.view`，页面权限按八个分区 view 权限集合判断；菜单、页面、操作仍独立校验。
2. 八个一级分区按参考顺序：基础信息、参数配置、数据字典、通知模板、对象存储、短信服务、邮件服务、App 版本。存储页标题使用“存储设置”。
3. URL canonical key：`basic-info`、`parameters`、`dictionaries`、`notification-templates`、`storage`、`sms`、`email`、`app-version`。兼容旧 `tab=settings`→参数配置。参考文档示例 `tab=dictionary` 与实际 `dictionaries` 不一致：升级时兼容别名并规范化 URL。
4. 默认首个有权分区；无权或不存在的 key 回退到首个有权分区并修正 URL；全部无权显示安全空态。直接访问、刷新、前进后退保持正确选中项，保留其他查询参数。
5. 仅活动一级页挂载，避免一次加载八页；离开有修改的表单前给出保存/放弃/取消保护。内部基础信息 Tabs 共享表单保留字段，存储提供商使用独立表单实例或仅挂载活动表单，不能复用参考的多个强制挂载 Form 共用实例。
6. 内层桌面左侧导航，≤640px 顶部导航；监听尺寸变化；中文/code 双行标签、连续分割线、hover、focus-visible、主题配色、内容顶部16px、统一 ListPageCard 壳层按参考对齐。
7. 统一 `AntdApp.useApp().message`；保存失败、网络异常、非法参数、测试失败使用浮动轻提示，不潜入页面排版。表单校验失败浮动说明首个字段并定位；成功可展示稳定结果摘要。参考的内嵌 MFA 错误文字及失败 Alert 不直接照搬。
8. 获取失败不能伪装成空列表/默认配置并允许保存；显示浮动错误、保留旧快照、提供重试；保存期间防重复提交。后台 refetch 不覆盖用户未保存输入。
9. 所有受权查询至少按 actor/session 与 workspace type/id 隔离，切换工作区和登出撤销未完成请求、清理私有缓存及编辑状态；公开品牌缓存单独管理。

验收：八分区不同权限组合、旧链接、非法链接、后退、刷新、窗口缩放、亮暗主题、键盘操作、慢请求切换、未保存修改与错误反馈；真实浏览器及 Electron 内页分别验证。

### U02 基础信息与品牌消费

完整字段：`companyName`、`brandLogoTextLong`、`brandLogoTextShort`、`icpRecord`、`longLogoFontSize/Family/Weight`、`shortLogoFontSize/Family/Weight`、只读 `updatedAt`。

- 品牌信息/主体信息两个内部 Tab，两个保存入口使用同一完整表单的 `form.submit()`。`preserve`、`forceRender` 保留隐藏字段；主体校验失败切换主体 Tab 并定位，错误浮动提示。
- 长文字最多20字符，短文字最多6字符；字号8—72整数；字体 `system/sans/serif/mono`；字重400/500/600/700。前端、handler、数据库一致校验，拒绝任意 CSS 和显式非法值。
- 默认长16px、短14px、system、600；旧请求缺少新增字体字段保留已保存值。空长 Logo 回退主体名，再回退产品默认名；空短 Logo 按中文前2字/去空白英文前6字符生成。
- 字体样式只影响后台左上角展开/收起 Logo；登录、注册、工作区选择页使用品牌文字但不应用这六项字体样式。
- 保留公开 `GET /public/platform-profile`、平台 GET/PATCH、`platform.basic_info.view/update` 和 `platform_profile.updated` 审计。只公开非敏感资料。
- Host 的 `platform-profile.tsx` 同步六字段、安全枚举映射、本地缓存兼容；保存后 query invalidate 并发 `ky:platform-profile-updated` 触发公共资料刷新。浏览器标题为“品牌 后台”，桌面程序页面标题为品牌；过期请求不能覆盖最新品牌。
- 为避免跨模块随意扩展 DOM 事件，沿用已有事件并同步契约；此阶段不引入新的 Electron IPC，也不迁移登录体系。

验收：两 Tab 任意保存不丢另一 Tab 字段；旧请求不重置字体；非法 CSS/范围/名称被拒；后台两种 Logo 状态即时生效，刷新/缓存/匿名登录页品牌与 ICP 一致；只读账号不能修改。

### U03 参数配置与 MFA 的真实范围

目标请求保持 `{settings:{security:{mfaEnabled:boolean}}}`；读取类型改为 `Record<string,unknown>` 或明确 JSON 类型，不再把对象字符串化。移除任意键新增/删除 UI。

- 参考 handler 只允许 `security` 顶层，必须含布尔 `mfaEnabled`；拒绝字符串、null、数组、缺失字段、空补丁、点号字面键及其他顶层键。security 内其他字段参考实现允许透传。
- 当前 Store 会删除未提交顶层 key。升级必须改为局部更新；服务端在事务中只修改 `security.mfaEnabled`，保留 security 内未知历史字段及其他顶层设置。不能仅依赖前端回传旧 security 快照，避免并发覆盖。
- 历史 `security` 为对象且缺少 MFA 值可显示未启用；已存在非法类型必须禁用保存并浮动提示，禁止自动覆盖。`security` 整体非法或点号旧键的修复需独立、可追溯迁移；先检测，不能直接删旧数据。
- 平台调用 `/platform/system-settings`，机构/企业调用 `/settings`，工作区查询 key 隔离，沿用对应 view/update 权限与审计。
- **实际消费**：两边 membership 的 `access_decision_store.go` 均读取平台 `security.mfaEnabled`，结合 session `mfa_verified_at` 校验高危 assurance；执行器操作确认消费该判定。机构/企业的同名值未被这条链读取，不能描述为已经生效的租户 MFA 策略。
- 未发现 auth 登录实现完整 MFA 注册/challenge/验证流程。当前开关不能宣传“全面启用登录 MFA”。界面明确当前生效范围；启用平台值前检测现有验证/恢复能力，避免管理员高危操作被永久阻断。
- 完整登录 MFA 和机构/企业策略继承作为 U10 依赖需求：由 auth 拥有验证事实，经受控接口提供，禁止配置页写入 `mfa_verified_at` 或自行充当认证成功证明。

验收：保存前后 hidden top-level/security 子键不变；并发编辑不丢数据；平台策略被高危操作读取；机构/企业设置不冒充全局策略；非法旧值可安全发现与修复；不能用配置保存成功证明 MFA 验证成功。

### U04 数据字典（只读）

完整结构：分类 `id/code/name/status/items`；条目 `label/value/sortOrder/status`。GET `/dictionaries` 可按 `code` 过滤；查询平台 `platform_root` 字典、按 code 排序，条目按 sort_order 排序。

每分类一个内部 Tab，双行中文名/code 标签；活动 key 在分类集合变化时回退首项。表格列标签、值、排序、状态；不分页，空分类有空态；normal/disabled 状态显示保留。沿用 `platform.dictionaries.view`，机构/企业无字典入口；不新增编辑、删除、导入能力。

验收：分类增减/空列表、条目排序、disabled 显示、中文与长 code、窄屏滚动和只读权限；请求失败不显示“暂无字典”假空态。

### U05 通知模板

完整结构：`templateKey/templateName/notificationType/title/content/description/enabled/updatedAt`。内置四类：`invitation`、`qualification_result`、`announcement`、`member_status`；变量分别为 inviter/workspace、qualificationType/result/remark、title/content、workspace/status。

- 列表查看、编辑名称/标题/正文/说明、启停、确认恢复默认；恢复默认会恢复名称、标题、内容、说明并启用。保留 readonly templateKey/type，无任意模板新增/删除入口。
- 既有 GET、PATCH key、PATCH key/status、POST key/reset 均保留；view/update 权限分离，操作审计保留。默认集由 migration 016 seed，当前 list 并没有旧文档说的首次访问自动 ensureDefault。
- **参考缺口**：全仓模板表引用只有 org 管理链，membership 的公告桥接等仍直接使用业务标题/正文；没有找到四类模板统一消费。管理页改了不代表通知已改。
- 升级补齐四场景真实消费，变量白名单和缺失变量错误明确，禁用模板不生成对应模板通知；不影响原业务状态提交。公告已发布通知保留快照，不追改历史。
- 遵守最新边界：org 仍拥有配置，membership/其他消费者通过受控 internal 模板解析接口取得渲染投影，不能照旧文档跨服务直接 SELECT 私表。内部请求带 request ID、安全引用、版本；若需可靠异步投递，用事务 outbox、幂等消费与重试，不仅 best-effort。

验收：四场景分别触发实际新通知；编辑、禁用、恢复默认都改变实际行为；缺变量被明确处理；通知内容和实际收件人权限正确；历史通知不改变。

### U06 多提供商存储（本次最大增量）

#### 配置与交互

提供商为 `local/minio/oss`。响应 `{activeStorageProvider,providers:{local,minio,oss}}`；每项完整字段：`providerKey/localDirectory/endpoint/region/bucket/bucketPrivate/forcePathStyle/prefix/publicDomain/accessKeyId/hasSecret/lastTestAt/lastTestStatus/lastTestMessage/updatedAt`。明文 `secretAccessKey` 仅输入；密文、配置指纹、测试指纹不得下发。

- 本地表单：目录（默认 `./storage`）、前缀、公网域名、访问权限；MinIO/OSS：Endpoint/Region/Bucket/AK/SK/前缀/域名/访问权限；仅 MinIO 显示 Path-Style 单选。私有/公共读映射 bucketPrivate。
- 三项独立保存与回填，区分“正在编辑的提供商”和“当前使用的提供商”；当前使用标签保留。保存不激活，切 Tab 不激活；激活必须显式“设为当前存储”。
- SK 留空保留，填写新值完成替换；不回填密码；保留兼容 rotate-secret API，UI 不必须有独立轮换按钮。
- 真正修改才弹放弃确认；按规范化字段快照检测 dirty，输入新 SK 也算修改。切换、保存、放弃更新各自快照；refetch 不强行切回当前 provider 或覆盖正在编辑的其他 provider。
- test 独立由 test 权限控制，无 update 权限也应可以测试已保存配置；加载、保存、测试、激活期间防错误操作。测试明确针对已保存版本，存在未保存内容时引导先保存。

#### 后端与激活

GET/PATCH `/platform/storage-setting`，POST `/test`、`/activate`、`/rotate-secret`；除 GET 外均明确 providerKey。参考写入将 `s3` 别名映射 minio；测试/激活/轮换目前只认三个枚举，升级兼容策略需一致。

- local 保存/测试/激活检查目录可创建和读写；云端必填 endpoint/bucket，激活还检查 AK/SK。SK 沿用 shared/crypto AES-256-GCM，环境 `KY_SECRET_KEY` 回退 `KY_AI_SECRET_KEY`，不得改变已有密文格式或自动更换主密钥。
- 每次实际配置变更/轮换产生新 revision/指纹并清空测试状态；测试结果绑定发起时的 revision；激活事务校验当前 revision 对应成功测试。不能复制参考“测试结束直接写当前 config_fingerprint”的方式：测试期间有保存时会错误认证未测试新配置。
- 激活与保存采用 CAS；测试与发送等外部副作用采用持久幂等。配置未变的普通保存可保留测试结果；变更后必须重测。失败持久化不能被 `_ =` 静默忽略。
- 本地测试执行临时写/读/校验/清理；云端参考仅 BucketExists（15秒），升级保留“连接测试”级别并增真实 Put/Get/Delete 探针证据。测试目录/对象唯一、失败清理可追踪，不写用户对象。
- 存储异常分类参考 config_missing、secret_missing、secret_unconfigured、secret_invalid、directory_missing、write_failed、connection_failed、bucket_missing；激活失败 `storage_not_tested`。结合已有错误码统一，避免将原始路径/签名 URL/供应商明文异常回显或入审计。
- 审计 updated、secret_rotated、tested、activated，包含 actor/workspace/provider/revision/result 安全摘要。

#### 消费与历史文件（不可遗漏）

参考项目新增 `ky-image-service`，上传按 active provider，读取/GC 按资源记录的 providerKey；local 实际根由 `KY_IMAGE_DIR` 提供，**并未读取系统配置的 localDirectory**。`bucketPrivate/publicDomain` 未进入该 Provider 行为；local 前缀也未被使用。管理页保存这些字段并不证明资源层应用。

当前项目没有该图片服务、shared/image、Core ImageUpload 能力。完整存储落地必须安排 U09 消费阶段，或在阶段验收中明确仅配置管理完成，不能宣称资源存储升级完成。

- 提供商配置的 owner 为 org；新增消费者通过受控内部接口获取限定配置/版本或调用存储 owner 能力。若跨服务共享物理存储适配器，将无业务工具下沉共享包，配置私表不能被另服务无约束穿透。
- 明确 localDirectory 相对路径解析基准，以服务部署的数据根为准；org 测试与实际消费者用同一规范化目录。不得仅显示“项目目录”却解析到不同 systemd WorkingDirectory。
- bucketPrivate 是访问策略意图，不代表自动改变云 Bucket ACL；publicDomain 只有经过业务访问授权/签名 URL 契约才能成为真实消费能力。未生效字段必须标明或完成接入。
- **历史资源须绑定不可变 storage location/version**（provider、bucket/root、prefix 等），不能只有 providerKey。参考读取/GC 用 providerKey 查最新配置，改同一 provider 的 Bucket/前缀会丢旧资源定位；升级应新增资源 location 版本引用，旧配置被引用时保留。
- 激活只切换后续新写入，不搬迁/删除已有文件；旧资源继续从旧 location 读取/回收。数据搬迁单独提供可重试、校验、回滚任务，禁止激活隐式搬迁。
- 图片上传、访问、绑定/解绑、业务 Logo 关联和到期 GC 均独立验收。人才/店铺专用分支不整包复制，当前不具备的业务仅保留扩展契约。

验收：三提供商 CRUD/密钥留空/替换、dirty/只读与测试独立权限；保存A→测试A并发保存B→B不可激活；目录与消费者一致；切换后旧图可读；同 provider 更换Bucket/前缀旧图仍可读；探针读写删除和失败清理；不泄露凭据。

回滚重点：P2字体列可保留；P3叶子更新回滚不能重新允许覆盖删除历史键；P4/P5已产生新provider/location资源后不能直接回滚旧单例消费者，需要保留兼容读者或先冻结上传并核对可读性。切回provider只影响新写入，不删除新存储中的旧资源。发生新业务写入后不得简单恢复整个旧数据库快照覆盖新数据；主密钥轮换与文件迁移单独制定回滚合同。
