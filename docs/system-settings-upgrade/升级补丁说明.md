## 5. 应用顺序与验证

在当前项目根目录，先检查：

```bash
git rev-parse HEAD
git status --short
git apply --check docs/system-settings-upgrade/patches/01-system-settings.patch
```

基线应为manifest记录的a9d1269；保留当前文档改动。正式应用主源码补丁时：

```bash
git apply docs/system-settings-upgrade/patches/01-system-settings.patch
git diff --check
corepack pnpm install --frozen-lockfile --ignore-scripts
corepack pnpm --filter @ky/admin-core build
corepack pnpm --filter @ky/plugin-system-settings typecheck
corepack pnpm --filter @ky/plugin-system-settings build
corepack pnpm --filter @ky/admin-host typecheck
corepack pnpm --filter @ky/admin-host build
go test ./services/ky-org-service/internal/server ./services/ky-org-service/internal/store ./shared/crypto
```

主包已按上述流程应用；原主包之外的数据库迁移器052限定兼容修正单独记录为03补丁。补充包尚未应用，不要紧接主包自动上线；先处理§4依赖并做独立隔离验证。

发布需要先执行078—081增量迁移，再启动依赖新增字段的org服务，再发布Host。部署前检查迁移ledger、目录权限、WorkingDirectory和ReadWritePaths。081会将无有效成功测试指纹的当前云提供商切到local，这是参考行为，需要在实际部署评审中核对现有文件和消费者；不能静默在生产执行。

升级后按八分区、公开资料、MFA存取与既有高危assurance、存储保存/测试/激活、旧链接、不同权限与Web/Electron窗口验证。短信/邮件测试会真实发送，本轮没有执行。字体数据库约束、文件目录权限、云连接、实际收件与视觉效果必须另有运行时验收。

回滚主源码可先 `git apply -R --check` 再反向应用。新增schema可暂留，数据库迁移不是反向git apply；081造成的active值切换需从备份/记录恢复。产生新的多提供商图片资源后，不可直接退回只识别旧单例的消费者。

## 6. 共同缺口不纳入本轮补丁

上一轮[需求与迭代方案](需求与迭代方案.md)中security叶子CAS、完整登录MFA、通知模板消费、云对象读写探针、不可变storage location、发送幂等/限频、SMTP变量与Reply-To、版本算法修复等属于另外的修复建议。当前升级补丁**不重新实现这些能力**，也不把它们变成本次升级前置开发任务。

仅在发布评审中披露会影响应用的事实：存储聚合API旧客户端兼容、081激活切换、目录与消费者不一致、图片业务依赖。后续如果要修复参考原有缺口，应另立最小修复补丁，保留本次来源与可追溯性。
