# 插件管理 R3 需求与实施方案（待锁定）

状态：R3 已按本地复审修订，方案已获授权；待锁定后按执行计划自动实施。本轮文档阶段不改产品代码。

## 1. 页面与范围

复用 `plugins/ky-system-settings`，路由 `/system/plugins`，导航“管理中心 → 系统设置 → 插件管理”。清单分后台业务插件和客户端宿主插件；关联服务仅作为依赖，不计插件，npm/Go 库不列入。首期只支持 `platform/platform_root`，菜单 `menu.platform.plugin_management` 与页面 `platform.plugin_management.view` 独立；owner/admin 默认 seed 仅按实际查询到的 `role_platform_owner`、`role_platform_admin` 授权。无安装、上传、卸载、启停、升级、回滚写入口，不采集其他设备。

## 2. 来源与组合边界

不存在服务端“当前 Mac 插件”统一 inventory，也不上送客户端清单回查。Host/Core 唯一注入只读 `PluginInventoryPort`，本地组合：

- Host 从实际 `localPlugins` 引用构建 manifest；每个 package.json 的版本构建注入并带 `buildId`，未导入模块不列。
- Desktop 通过 `desktop-plugins:inventory` 纯 Query 返回当前 active 实例安全投影；无 active 不以 builtin 冒充。
- HTTP 仅有 `GET /api/v1/platform/plugin-management/service-health`，归 `ky-org-service`，无新表、服务或账号。

Port 本地处理最多 200 项的 keyword/type/loadState/runtimeState 筛选、分页、排序和详情；HTTP 不存在 inventory/{id} 路由。

## 3. DTO 与状态

字段固定：`id`、`name`、`description`、`type`、`version`（`string|null`）、`buildId`（`string|null`）、`location`、`provider`、`capabilities`、`compatibleHost`、`pluginApi`、`uiApi`、`candidateVersion`、`rollbackVersion`、`availability`、`enabledState`、`loadState`、`runtimeState`、`uiConfirmationState`、`updatePhase`、`signatureState`、`services[]`、`sampledAtUtc`、`freshness`、`errorReason`、`lastSuccess`、`lastUpdateResult`、`lastRollbackResult`。可选元数据缺失为 null；状态未知使用枚举 unknown。

枚举：availability=`supported|not_supported|unknown`；enabledState=`enabled|disabled|not_applicable|unknown`；loadState=`loaded|not_loaded|loading|failed|unknown|not_applicable`；runtimeState=`running|unresponsive|stopped|unknown|not_applicable`；uiConfirmationState=`confirmed|unconfirmed|not_applicable|unknown`；signatureState=`verified|builtin_trusted|unverified|unknown|not_applicable`；freshness=`fresh|stale`。service 元素固定 `{key,state,reason,checkedAtUtc,version}`，state=`healthy|unhealthy|timeout|unknown|not_applicable`。

后台静态 import 成功只映射 `loadState=loaded`（“已加载”）；enabled/runtime 均为 `not_applicable`。Desktop `running` 必须 active 存在、未 revoked、webContents 未销毁、ready=true 且 heartbeat 距当前不超过 6500ms；stable phase 不推出实例健康。窗口隐藏/最小化仅影响 UI confirmation，不把实例改 failed。无 active 不 fallback builtin；候选未安全加载只显示已知版本或 null。签名 verified 只来自实际验签，内置来源为 builtin_trusted。

## 4. 菜单与路由权限

当前 `apps/ky-admin-host/src/app.tsx:354-365` 的 `menuVisible` 只检查 `requiredPermission/requiredAnyPermissions`，且调用位于 `:594` 主菜单、`:617-618` workbench 菜单和子菜单。R3 修复要求三处同时消费当前 workspace 的 `menuKeys`：菜单带 `menuKey` 且 key 以 `menu.` 开头时，必须同时满足 `menuKeys` 与页面/权限条件；旧非 `menu.` key 保持旧行为。路由仍单独执行 `requiredPermission/requiredAnyPermissions`（`:340-351`），不可用菜单判断路由授权。自动化用例覆盖 menu 有 page 无、page 有 menu 无、legacy menu 不回归及三处子菜单。

## 5. Desktop Query 合同

新增 `desktop-plugins:inventory` 纯 Query，无订阅/事件、不注册 UI 租约、不调用 snapshot、不生成 challenge。输入严格只能 `{}`，拒绝缺字段以外的多余键；请求/响应 payload 上限 64KiB，最多 200 项。仅 main 顶层 frame sender；offline、plugin、unknown、子 frame 一律拒绝。返回只读快照，不含 confirmation/challenge、私路径、key、token、Cookie、Storage。Host adapter 注入安全 `PluginInventoryPort`，业务页面不得访问 `window.aicrm` 或 Electron IPC。调用前后 `uiMembershipRevision`、challenge、ACK 必须不变；旧 Host 返回 not_supported。

## 6. 采样与故障

页面可见时每 30 秒轮询；采样 TTL 固定 90 秒。来源失败立即将该来源状态设 unknown，同时保留 lastSuccess，不能继续绿色。时间保存 UTC、显示 Asia/Shanghai；过期依据本地单调接收时间。每次响应带 generation，使用 AbortController；退出、logout、离开 platform、注销、撤权取消 timer/请求并丢弃迟到结果。单次 native query 客户端超时 3 秒。Desktop 失败不丢后台行；普通浏览器不生成假 desktop 行，显示“不支持检测”。

## 7. 固定服务健康

白名单映射从 `ops/kww` 实际文件读取并在实现前复核：`auth=127.0.0.1:18081`、`org=18082`、`membership=18083`、`matrix=18085`、`ai-model=18086`，路径均 `/readyz`。插件映射：identity→auth+membership，organization→org，access/audit/notification→membership，matrix→matrix，aiConfiguration→ai-model，systemSettings→org。店铺 18102 排除。

每服务超时 2 秒、总超时 5 秒、并发 4；不跟随 redirect、不用系统 proxy、不转发用户 headers/token；响应体上限 4KiB，必须是合法 JSON 且 `status=ok`、`service` 与目标服务名一致，否则 `invalid_response`。200 仅表示服务就绪，不代表业务功能；版本未知为 null。浏览器不能提交 URL/host/port。

## 8. 权限与后端

后端由 `shared/auth` 验证 JWT actor/session，再调用受控 Membership AccessDecision；必须匹配 `actor`、`ws=platform_root`、`membershipId`、`requiredGrant=platform.plugin_management.view`、`scope=all`。AccessDecision 失败 fail-closed；超时返回 503 安全 reason，不误报 403；500 只返回安全 reason。未知/空/混合 scope 拒绝，不读取 Auth/Membership 私表。handler 独立于既有 org 接口；HTTP 标准携带 Bearer、workspace headers、requestId。
