# 插件管理 R2 需求与实施方案（待锁定）

状态：R2 已按本地复审意见修订，尚未锁定、未实现、未迁移、未部署。

## 1. 产品边界

页面固定为现有 `plugins/ky-system-settings` 内路由 `/system/plugins`，导航为“管理中心 → 系统设置 → 插件管理”。清单分为后台业务插件与客户端宿主插件；关联服务只作为依赖，不计为插件。npm/Go 库不列入。首期范围固定为 `platform/platform_root`，权限为 `menu.platform.plugin_management` 与 `platform.plugin_management.view`；owner/admin 默认授予，角色 ID 以实际 seed 查询为准。无安装、上传、卸载、启停、升级、回滚写入口，不采集其他设备。

## 2. 唯一数据来源

不存在服务端直接返回“当前 Mac 插件”的统一 HTTP inventory，也不上传客户端清单再回查。Host/Core 注入一个只读 `PluginInventoryPort`，在本地组合三类来源：

1. Host 从实际 `localPlugins` 引用生成后台 build manifest；版本从各 package.json 构建注入，并包含 `buildId`。未导入模块不列。
2. Desktop 通过纯 Query IPC `desktop-plugins:inventory` 返回当前 active 实例安全投影；没有 active 时不以 builtin 代替。
3. 后端仅提供 `GET /api/v1/platform/plugin-management/service-health`，归 `ky-org-service`，无新表、无新服务、无新数据库账号。

`PluginInventoryPort` 在本地完成最多 200 项的筛选、排序、分页和详情组合；HTTP 不提供 `/inventory` 或 `/inventory/{id}`。

## 3. DTO 与状态维度

列表/详情字段固定：`id`、`name`、`type`、`version`（`string|null`）、`buildId`（`string|null`）、`location`、`availability`、`enabledState`、`loadState`、`runtimeState`、`uiConfirmationState`、`updatePhase`（真实 phase 或 null）、`signatureState`、`services[]`、`sampledAtUtc`、`freshness`、`errorReason`、`lastSuccess`。缺失字段使用 null，不使用字符串 unknown。

枚举固定：

- `availability`: `supported|not_supported|unknown`
- `enabledState`: `enabled|disabled|not_applicable|unknown`
- `loadState`: `loaded|not_loaded|loading|failed|unknown|not_applicable`
- `runtimeState`: `running|unresponsive|stopped|unknown|not_applicable`
- `uiConfirmationState`: `confirmed|unconfirmed|not_applicable|unknown`
- `signatureState`: `verified|builtin_trusted|unverified|unknown|not_applicable`
- `freshness`: `fresh|stale`

后台插件静态 import 成功仅映射 `loadState=loaded`（中文“已加载”），不映射 running；后台 `enabledState=not_applicable`、`runtimeState=not_applicable`。客户端 `running` 必须同时满足 active 实例存在、未 revoked、webContents 未销毁、ready=true、heartbeat 距当前不超过 6500ms；不从 phase=stable 推导健康。主窗口隐藏/最小化导致 UI confirmation 不可用时，只降低 `uiConfirmationState`，不把运行实例改为 failed。候选若未安全加载，只显示已知 version，否则 null；signature 仅实际 verify 证据，内置为 `builtin_trusted`，digest 存在不等于 verified。

## 4. IPC 与 Host 适配

新增 `desktop-plugins:inventory` 是纯 Query，无订阅和事件，不注册 UI 租约、不调用 snapshot、不生成 challenge。输入固定为空对象 `{}`（允许无参数但实现统一使用空对象），请求 payload 不超过 64KiB，结果最多 200 项。仅允许 main 顶层 frame sender；offline、plugin、unknown、子 frame 一律拒绝。全入口显式 allowlist、生命周期注销和窗口销毁清理。

Host adapter 注入安全 `PluginInventoryPort` 对象；业务页面不得访问 `window.aicrm`、token、Electron IPC、confirmation/challenge、运行私路径或 key。旧 Host 无此通道时返回 `availability=not_supported`，不影响后台清单。

## 5. 采样、刷新和故障

页面可见时每 30 秒轮询；每次采样 TTL 固定 90 秒。采集失败立即将对应来源置 `unknown` 并保留 `lastSuccess`，不能在 TTL 内继续显示绿色。服务端采样时间以 UTC 保存，界面以 Asia/Shanghai 显示；过期依据本地单调接收时间，避免服务端时钟偏差。每次响应带 `generation`，请求使用 `AbortController`；退出、logout、workspace 切换、注销或撤权时取消并丢弃迟到结果。Desktop 失败不丢失后台列表；普通浏览器不生成假 desktop 行，只显示“不支持检测”能力提示。

## 6. 服务健康合同

固定 service key→端口→readyz 清单来源为 `ops/kww`，manifest 与清单必须一致；店铺服务 `18102` 在未发布前排除。每服务超时 2 秒，总超时 5 秒，并发上限 4；不跟随 redirect、不使用系统 proxy、不向 readyz 转发用户 token，响应体上限 4KiB。200 仅表示服务就绪，不代表业务功能通过。超时、连接失败、非 200、格式异常使用不同 `errorReason`；服务版本未知为 null。浏览器永不提交 URL、host 或端口。

HTTP 请求携带标准 Bearer、workspace headers、requestId；后端每次重新执行 actor/session/workspace/permission/data scope。只支持 scope `all` 且仍 AND 当前 `platform_root`；未知、空、混合 scope 拒绝。不得读取 Auth/Membership 私表，不大改既有 org 接口，使用独立受控 handler。

## 7. 发版隔离和兼容

新任务构建使用独立暂存目录，复制待发布源码但排除 env、key、用户数据；暂存 manifest 明确排除未完成 `shop-management` import/entry/依赖，不修改工作区现有店铺 dirty，不发布店铺服务、迁移或菜单。现有 `desktop-plugin-releases` 静态资产保留。

本轮新增 native Query 能力需要更新一次客户端；后续插件包更新继续使用现有宿主兼容机制。V3 已获本地 Mac 构建、启动和验收授权；正式发行、公证、非 Mac 与全设备采集不在首期范围。
