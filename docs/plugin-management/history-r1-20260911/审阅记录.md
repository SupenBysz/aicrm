## P0 问题

1. **P0：实际运行与声明来源未分离。** 静态注册、目录、package version 或 release index 都可能与 active 不同。闭环：build manifest、Host runtime confirmation、Desktop snapshot 三层字段独立；缺证据为 `unknown`。
2. **P0：跨 workspace/权限泄露风险。** 聚合页若复用全局最强权限或缓存，可能越权。闭环：仅 `plugin_management.view` + 当前 workspace AccessDecision/data scope；logout/workspace 切换取消请求并清 cache。
3. **P0：任意 URL 健康探测形成 SSRF。** 闭环：服务端固定 service key→readyz 映射、超时/无任意 redirect；浏览器永不传 URL。
4. **P0：新增 Desktop IPC 破坏 sender gate 或 UI ACK。** 闭环：显式 channel/角色/schema/大小限制，拒绝未知/子 frame，复用既有 lifecycle，旧 Host 明确降级，不创建第二 UI 租约。

## P1 问题

1. **P1：版本与签名语义混淆。** `package.json`、active digest、candidate、release sequence 分列；缺失版本/签名为 unknown。
2. **P1：状态 TTL 和异常优先未定义会造成过期绿灯。** 固定 UTC 采样、30 秒刷新、90 秒过期；过期统一 unknown，异常筛选只改变排序。
3. **P1：服务依赖重复计数。** 采用 `service.key` 依赖字段，不生成插件条目；无法采样返回 unknown。
4. **P1：普通浏览器/旧客户端能力差异。** adapter 返回 not_supported，不伪造 desktop 状态；详情标明 capability source。
5. **P1：宿主升级边界被误解为插件包永远独立更新。** 新 native Port/IPC 需宿主升级；仅在兼容宿主上允许后续包更新。
6. **P1：部分来源失败导致整页不可用。** 每项保留 source/error 分类和 sampledAt，单来源失败不覆盖其他来源；请求取消和卸载清理。

## 技术选择

- 后端优先复用现有系统设置/组织服务路由，无新表、无新 DB role；服务健康采用固定白名单 readyz adapter。
- Host 生成 manifest；Desktop 只读 InventoryPort 复用当前 active snapshot，新增 query 走集中 IPC；业务插件不直接访问 native bridge。
- 页面首期只读、平台 `plugin_management.view`，菜单与 page permission 分开；详情严格脱敏。
