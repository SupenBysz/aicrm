# 插件管理 R1 需求与方案（候选）

状态：R1 仅完成源码事实审阅，未锁定、未实现、未迁移、未部署。

## 1. 目标和边界

管理中心新增“系统设置 → 插件管理”。页面将后台业务插件与客户端宿主插件分成两类，呈现统一的只读清单；关联服务作为依赖健康信息展示，不单独计入插件。npm/Go 库不进入清单。首期只授予平台 `plugin_management.view`，默认管理员角色可见；不提供安装、上传、卸载、启停、升级或回滚写入口，也不采集其他设备。

普通浏览器和旧客户端没有相应能力时显示 `not_supported` 或 `unknown`，不能用目录存在、源码注册、HTTP 成功或最新发布版本冒充实际运行状态。页面可见时刷新；采样时间使用 UTC。建议刷新周期 30 秒、90 秒过期，过期状态降为 `unknown`，不继续显示绿色健康。

## 2. 源码事实

- 当前 Host 清单在 `apps/ky-admin-host/src/local-plugin-manifest.ts:1-22`，现有 9 个注册项（含已生成的 shop），仅含插件对象，没有统一版本/运行状态字段；`package.json` 版本目前各插件多为 `0.1.0`（例如 `plugins/ky-notification/package.json:3`）。
- Host 通过 `localPlugins` 生成路由和导航，`apps/ky-admin-host/src/app.tsx:126,587-618`；这证明注册与可见菜单，不证明插件已加载或稳定运行。
- Desktop 宿主当前单一状态栏插件协议位于 `apps/aicrm-desktop/src/main/desktop-plugin-host/host.ts:51-106`；`snapshot()` 仅返回当前 active 插件的 digest、pluginVersion、phase、items 和 UI confirmation（约 `:71`），没有全插件 inventory 或服务健康 API。
- 只读桥在 `apps/aicrm-desktop/src/preload/plugin-host-bridge.ts:4-10`，既有通道是 register/unregister/snapshot/ack/action；新增查询必须显式加入 constants、类型、handler、sender gate 和生命周期清理。
- 插件隔离会话、CSP、permission handler、webRequest 和 sandbox 在 `host.ts:73-77`；main 不应引入 RBAC、workspace 或业务 token。
- 后端服务均提供 `/readyz`/`/healthz`，例如 `services/ky-membership-service/internal/server/server.go:38-40,118-136`；服务边界规定领域 API 归属，不能从页面任意探测 URL。
- Admin 权限消费在 `packages/ky-admin-core/src/permissions.tsx:51-67`，Host 菜单/页面/操作权限是不同维度；不能只隐藏菜单当作后端授权。

## 3. 候选数据来源和状态模型

### 3.1 后台业务插件

由 Host 构建时生成声明式 `build manifest`（插件 ID、中文名、类型、构建版本、归属服务 key、能力摘要），运行时只将实际挂载且页面初始化确认过的插件标为 `running`。manifest 来源不等于运行事实；构建版本从插件 package/build 注入，缺失显示 `unknown`，不取最新 release 代替 active。

### 3.2 客户端宿主插件

由 Desktop Host 的只读 `InventoryPort` 提供当前宿主 active 实例的安全投影：真实 plugin ID、manifest version、digest、phase、active revision、候选版本、回滚目标和最近安全异常。现有协议只支持单插件 statusBar UI；无法证明全插件 inventory 时只返回该插件，其他项为 `not_supported`。不得注册第二 UI 租约或干扰既有 statusBar ACK；旧客户端没有新 IPC 时 Host adapter 降级为 `not_supported`。

### 3.3 精确状态枚举

`installed`（声明已安装且本次采样有实例）、`running`（握手/心跳/声明式 UI 可信且 TTL 未过期）、`stable`、`candidate`、`probation`、`draining`、`failed`、`disabled`、`unknown`、`not_supported`、`not_applicable`。插件运行状态与关联服务状态分开；服务状态为 `healthy|unhealthy|timeout|unknown|not_applicable`。未取得真实签名、版本或运行证据显示 `unknown`。

`running` 必须同时满足：当前 session/navigation/revision/digest 的可信 UI confirmation、最近 heartbeat 在 TTL 内（建议 90 秒）且 Host 没有异常终态。只收到 HTTP 响应、目录存在、注册对象存在或候选索引存在，均不得映射为 running/stable。

### 3.4 固定 DTO（候选）

`GET /api/v1/plugin-management/inventory` 返回统一 envelope 和分页：

```json
{"data":{"items":[{"id":"opaque","name":"中文名","type":"admin|desktop","version":"0.1.0|unknown","location":"host|client|unknown","enabled":"enabled|disabled|unknown","runtimeState":"running|stable|candidate|failed|unknown|not_supported","service":{"key":"ky-auth","state":"healthy|unhealthy|timeout|unknown|not_applicable","sampledAt":"UTC"},"sampledAt":"UTC"}],"pagination":{"page":1,"pageSize":20,"total":0}},"requestId":"..."}
```

查询参数固定 `page`（默认 1）、`pageSize`（默认 20，上限 100）、`type=admin|desktop`、`runtimeState`、`enabled`、`keyword`、`异常优先`。`total` 在同一权限和 workspace predicate 后计算；请求取消、logout、workspace 切换清理缓存和未完成请求。

详情 `GET /api/v1/plugin-management/inventory/{id}` 只返回安全元数据、能力/依赖兼容摘要、异常摘要、客户端签名状态、更新 phase、candidate/rollback 结果；不返回 token、路径、Cookie、Storage、原始日志、私钥或凭据。

## 4. 服务归属和健康采样

首期不新建数据库表和独立数据库账号。插件清单查询归现有系统设置/组织领域的受控 backend 路由（候选 `/api/v1/plugin-management/inventory`），后端固定映射已登记服务的 `/readyz` 目标与超时；不接受浏览器传入任意 URL，不跟随任意重定向，不形成 SSRF。无法取得服务版本/签名时返回 `unknown`。服务依赖不作为插件条目计数。

所有请求由 Host request client 注入 Bearer、workspace headers、requestId；后端重新计算 actor、workspace、`plugin_management.view` 和 data scope。平台、agency、enterprise 不自动继承；首期页面只支持当前 workspace 的安全摘要，未知 scope fail-closed。

## 5. Desktop 注入候选

Host/Core 注入只读 `InventoryPort`，业务插件只能通过 Host adapter 使用，禁止业务插件直接读取 `window.aicrm`、token 或 Electron IPC。新增 native query 必须固定 channel、JSON schema、payload 上限、allowlist sender（main/受控窗口；拒绝未知与子 frame）、导航代次校验和 dispose 清理。旧 Host 无该 channel 时返回 `not_supported`。订阅按事件通信规范先订阅再快照，gap/epoch 变化丢弃增量并重读；不得新增第二 UI registration。

## 6. 与店铺模块和宿主合同的隔离

`ky-shop-management` 当前处于 D1a/D1b 待交叉复核、D2 未实现状态；本模块的 docs、权限 seed、路由、构建和部署清单不得修改或发布它。插件管理只读聚合其安全声明（若尚未构建则 unknown），不依赖店铺迁移完成。

现有宿主插件合同要求 `desktop-plugins/` 与 `plugins/ky-*` 分离；新增只读 InventoryPort、菜单或 IPC 属于宿主/Host 变更，首轮可能需要客户端更新。后续插件包更新不等于宿主安装包永远无需更新；只有在宿主已支持该 Port、协议版本和 UI 槽时，才可仅更新插件包。

## 7. 候选实施选择与未决门禁

候选采用：Host build manifest + Desktop 单插件安全投影 + 固定服务 readyz adapter + 无数据库表 + 平台 `plugin_management.view`。P0/P1 问题和处置见《审阅记录.md》；验收映射见《验收与任务依赖.md》。本文件不是锁定合同，任何实现前需本地交叉复审并生成锁定快照。
