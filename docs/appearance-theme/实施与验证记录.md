# 多配色外观主题实施与验证记录

日期：2026-10-29。关联：[需求与迭代方案](需求与迭代方案.md)。

状态：本轮功能已在工作空间实现，完成本地构建、独立数据库、API 与部分真实 Web／macOS 客户端验证；尚未提交、推送或部署准生产环境。本文不将本地验证等同线上及全部业务验收。

## 1. 已实现的功能

- 三套配色：经典金、商务蓝、翡翠绿，每套包含亮色和暗色；模式独立支持跟随系统。
- 系统配置新增“外观主题”页签，位于基础信息与参数配置之间，支持 URL 定位。所有已获准进入系统配置的账号可在此设置本人外观；平台默认区另按专用权限显示。
- 个人选择立即应用并自动保存；平台默认仅在点击保存后提交。平台草稿局部预览，不修改全局主题。
- 顶部外观面板与系统配置共享状态，可切换主题、跟随平台、显示保存状态及重试。
- 按账号隔离本地缓存，服务端保存账号偏好；清除覆盖使用 source=platform 且 themeId/mode 为空，保留 revision，避免删除后版本重置导致旧请求复活。
- 自动保存串行化、短防抖、revision 检查；失败保留本机选择，不自动覆盖服务器新值；丢失响应但实际已提交时，可重试核对结果。
- 系统配置平台草稿在当前浏览器标签页的 sessionStorage 中按账号暂存，切换页签后可恢复；刷新离开有未保存提示。
- 首屏读取轻量快照，运行时同步 CSS、Ant Design 和原生窗口背景；旧 light/dark 迁移不自动上传到账号，并保留旧版明暗投影。
- 新增独立平台查看／修改权限及中文资源名称；仅现有正常的平台 owner/admin 系统角色初始化获得新权限。

## 2. 实现位置与职责

| 范围 | 文件或目录 | 职责 |
| --- | --- | --- |
| 主题内核 | `packages/ky-admin-core/src/theme/` | 类型、三个主题、经典金兼容基线、CSS 变量、Ant Design 映射、共享上下文与控件 |
| Host | `apps/ky-admin-host/src/appearance-*`、`app.tsx`、`app-store.ts` | 首屏、账号生命周期、同步和顶部入口 |
| 设置页 | `plugins/ky-system-settings/src/pages/appearance-page.tsx`、`settings-hub-page.tsx`、插件 routes/index | 系统配置入口、个人与平台两区、草稿和权限 |
| 服务合同 | `shared/appearance/` | 受控主题／模式、版本、严格且限制长度的 JSON 输入 |
| Auth | `services/ky-auth-service/internal/{server,store}/appearance*` | 本人偏好，actor 只从认证会话取得 |
| Org | `services/ky-org-service/internal/{server,store}/appearance*` | 平台默认、条件保存、事务变更历史与管理审计 |
| 数据库 | `ops/db/106_appearance_themes.sql` | 两类配置表、平台变更表、权限和初始化角色绑定 |
| 权限与网关 | `permission-labels.ts`、Native/K3s nginx、`shared/domainentry` | 中文目录、转发、受控公共读取路径 |

平台默认采用独立表，通用参数接口原有 security 白名单保持不变。平台审计事务表为 `ky_platform_appearance_change`；现有管理审计日志另记录 `appearance.updated`。

## 3. API 合同

所有业务响应继续使用现有 data/error/requestId 包装。

| 方法与路径 | 身份／权限 | 数据 |
| --- | --- | --- |
| GET `/api/v1/public/appearance` | 公共安全配置 | 平台默认及 revision，Cache-Control: no-store |
| GET `/api/v1/auth/me/appearance` | 有效本人会话 | 本人覆盖或跟随平台记录；private, no-store |
| PUT `/api/v1/auth/me/appearance` | 有效本人会话 | 完整本人偏好及预期 revision |
| GET `/api/v1/platform/appearance` | platform.appearance.view | 平台当前配置 |
| PUT `/api/v1/platform/appearance` | platform.appearance.update | 完整默认配置及预期 revision |

公共接口只返回主题、模式、版本等外观字段，不提供系统参数、操作者或变更历史。公共可见不表示可以进入平台管理页。

请求示例（本人选择）：

```json
{"schemaVersion":1,"source":"personal","themeId":"business-blue","mode":"dark","revision":0}
```

本人恢复跟随平台：

```json
{"schemaVersion":1,"source":"platform","themeId":"","mode":"","revision":1}
```

平台默认 source 必须为 platform，主题和模式必须有效且非空。保存成功 revision 加一；过期版本返回 409 / appearance_conflict。非法值、未知字段、多段 JSON 或超长输入拒绝。客户端不能指定其他目标用户。

## 4. 颜色审计及适配决策

| 来源 | 处理 |
| --- | --- |
| Host 外壳及语义变量 | 使用主题解析结果；保留经典金兼容变量，移除重复系统明暗覆盖 |
| Host 固定表面色／编辑器浮层 | 将表面、边框、选中态改为语义变量；错误／成功及查找高亮不替换为品牌色 |
| 公共组件与插件的 Ant Design 控件 | Vite dedupe react/react-dom/antd/icons，统一 ConfigProvider 上下文 |
| 公共品牌表单 | 上传卡片随主题，亮暗预览消费同一配色；图片底板和原图固有颜色保留 |
| Monaco | 根据当前配色与最终明暗更新主题，不销毁模型；补全候选同步语义颜色 |
| 脚本静态高亮 | 增加亮暗语法语义变量；保留 token 类型区别 |
| 矩阵账号终端 | 工具栏／页脚与应用配色同步；ANSI 输出的固定暗色底和状态含义色保留 |
| AI 原始日志终端 | 固定技术输出暗色底与 ANSI 内容色保留；外围控件由公共主题消费 |
| 执行器事件 | 中性透明边框／背景保留，不作为品牌主色 |
| 原生控制条 | 已有宿主语义变量继续使用，增加原生窗口背景同步 |
| 外部网页／受控登录网页 | 不注入换色样式、不隐藏、不重建；仅原生加载背景衔接 |

发现并修复的实际问题：公共包解析到 Ant Design 6.4.4，而宿主解析到 6.5.0，导致一部分公共控件不消费宿主 ConfigProvider。通过构建解析去重解决，构建模块数也相应下降。没有修改依赖锁文件或新增运行时依赖。

## 5. 已执行验证

### 5.1 自动检查

- Shared appearance 合同测试：三主题、三模式、个人／平台语义、非法配置。
- 主题 Node 测试：全部预设和亮暗变量完整性、移除主题回退、system 解析及根节点更新。
- Auth／Org 的 server/store 测试及 race 检查。
- 两个独立测试数据库内运行真实 PostgreSQL 并发保存：同一 revision 两个请求只能一个成功；另一个返回冲突。
- Auth 数据库验证用户隔离、恢复跟随及递增 revision。
- Org 数据库验证审计事务写入；审计表不可写时配置更新整体回滚。
- 现有数据库部署脚本测试通过；迁移 106 在本地克隆数据库通过正式 ledger runner 执行并重复运行，登记 filename/revision 正常。
- Admin Core 构建、Host 类型检查与构建、Desktop 类型检查与构建通过。

构建保留既有体积及动态导入提示；未将其描述为本轮新增功能故障。

### 5.2 本地 API 验证

通过本地真实 Auth／Org／Membership 与 nginx 路由规则生成的代理验证：

- 三主题 × light/dark/system 均可保存。
- 未登录本人接口 401；有平台成员身份但无外观权限的账号读写管理接口 403。
- 个人／平台过期 revision 返回 409；非法主题、任意 userId 字段返回 400。
- 第二账号的个人选择不改变第一账号。
- 平台默认公开读取随保存更新，已有个人覆盖保持不变；清除本人覆盖后返回跟随平台。
- 通用 system-settings 写 appearance 被拒绝，不能绕过专用写权限。

测试均在本地 `kycrm_test_appearance_*` 数据库完成，未修改准生产数据库。

### 5.3 真实界面和客户端

- Chrome 中实际进入 `/w/platform/platform_root/system?tab=appearance`，确认页签、个人／平台分区及配置恢复。
- 浏览器实际完成商务蓝／翡翠绿切换与自动保存、刷新恢复。
- 使用当前项目 Electron 构建和独立临时 userData 启动本地客户端，登录后恢复浏览器已保存的经典金暗色账号偏好。
- 客户端顶部快捷面板逐项切换经典金、商务蓝、翡翠绿的亮暗六组合，控件状态及“已保存”反馈正常；实际查看了客户端面板视觉。
- 独立客户端的 `appearance.json` 随服务端默认／账号偏好改变，确认新的受控 IPC 已到达主进程并执行原生背景同步。

本地验收入口为 `http://127.0.0.1:25441`，仅供当前机器临时测试，不是对外发布地址。

## 6. 发布顺序与回退

1. 确认备份和迁移 ledger；运行迁移 106。
2. 若安装使用服务分离数据库角色，按 `ops/db/roles/appearance.sql.example` 只授予对应服务所需的新表权限。
3. 发布 Auth 和 Org，再发布包含新增代理规则的 Host；核验角色权限刷新及实际菜单可见性。
4. 发布新 Desktop 才能获得原生背景桥接；旧客户端继续使用 Web 配色，原生窗口背景不能声称已经同步。
5. 若需临时停用新主题，以 `VITE_APPEARANCE_DISABLED=1` 重新构建 Host。此开关在外观配置之外，保留账号及平台数据；恢复时重新构建启用。
6. 回滚旧 Host 时可消费已投影的 light/dark key；新数据表保留。不能通过删表回滚界面。

## 8. 个人偏好入口迭代（2026-10-29）

### 已实现

- 工作台／管理中心的用户下拉增加“个人偏好”，置于修改密码之前；保留工作区切换条件与退出分隔线，移除独立主题快捷按钮。
- 右侧侧滑采用固定标题栏、正文独立滚动，并测量避让宿主 Header 与桌面状态栏。本人偏好自动保存，无额外保存／取消按钮。
- “使用平台默认”开启时禁用个人控件；关闭时复制平台的配置值，包括 `system`，不将当前解析出的亮暗色写回为固定模式。
- 根级 Provider 持续拥有状态和保存队列。关闭侧滑不会取消同步；锁屏、账号／工作区变化时收起侧滑，相关 Header 浮层互斥。
- 以结构化元数据展示来源和同步阶段。显式重新读取会取消未发出的保存、阻止并发选择，并同时读取本人设置与平台默认；读取失败保留本机选择。
- 正在保存和保存结果不确定时禁止重新读取。不确定结果须先重试核对服务端 revision 和值，区分已保存、可重发、版本冲突；跨窗口缓存不能打断当前读取或写入。
- 系统配置仅保留平台默认设置、权限控制、草稿、预览和保存；重新读取草稿前确认，读取期间禁止编辑。无权／无效页签回退首个有权页签，用 replace 规范 URL；参数配置旧别名兼容。
- 本入口迭代没有新增后端、迁移或权限码，沿用前述主题能力。

- Core、系统配置插件 TypeScript 构建及 Host 类型检查、生产构建通过；Vite 仍提示既有主包体积较大。
