# 达人广场独立 WebView 模块需求与迭代方案

日期：2026-10-15。状态：用户已确认方案，本轮仅保存文档，尚未开始模块开发。

## 1. 目标

以当前“工作台 → 达人广场 → 抖音”的页面效果为基础，封装独立的达人广场 WebView 页面模块，替换该菜单当前打开的模块，作为后续定制的基础。

先完成独立封装和菜单接入，初始显示与操作保持现有效果；具体业务定制在后续迭代提出。本文是确认后的需求基线，不代表已完成源码调研或实现，具体文件、路由与接口映射在实施前核验。

## 2. 范围与预期行为

| 项目 | 预期行为 |
| --- | --- |
| 菜单入口 | 保留“达人广场 → 抖音”的名称、图标、排序及授权关系 |
| 页面模块 | 菜单指向新封装的达人广场页面，拥有独立组件和配置入口 |
| 初始效果 | 沿用当前布局、工具栏、加载占位、错误提示与重试交互 |
| WebView 能力 | 复用现有创建、导航、会话隔离、脚本与插件注入能力 |
| 页面状态 | 切换工作台、管理中心后返回时保持页面状态，避免重复创建或刷新 |
| 内容布局 | 填满内容区域，保持当前统一边距 |
| 后续定制 | 可独立调整工具栏、默认地址、页面交互、脚本与样式，不影响其他 WebView 页面 |

## 3. 模块边界

### 达人广场业务页面

负责页面布局、业务工具栏、默认地址、业务状态，以及达人广场专属脚本和样式配置。提供明确、集中的定制入口，后续定制修改优先落在此模块内。

### 共用 WebView 基础层

继续负责窗口创建、尺寸同步、会话、安全校验、导航和注入机制。新模块调用现有基础层，不重新维护一套底层 WebView 实现。

独立页面模块不等于新增登录空间或要求重新登录。初始接入保持现有会话来源、资源授权规则及安全边界；后续确有隔离需求时再单独调整。

## 4. 实施步骤

1. 核验现有菜单到页面的路由、配置和权限映射，梳理 WebView 生命周期、状态保留、会话与注入依赖。
2. 提取达人广场独立页面模块和配置入口，复用共用 WebView 基础层，保持初始效果与操作一致。
3. 将现有抖音菜单接入新模块，保持菜单标识、名称、图标、排序、授权关系和原有配置语义。
4. 核验页面切换、返回、关闭再打开、初始化失败和重试；处理重复实例与残留资源。
5. 明确定制入口及回退方式，为下一轮业务调整提供依据。

## 5. 验收标准

1. 点击现有“工作台 → 达人广场 → 抖音”实际进入新模块，无需用户手动修改菜单。
2. 初始显示和操作与当前效果一致，内容区域完整填充，边距统一。
3. 新模块具备明确、集中的定制入口，修改它不影响矩阵账号或其他 WebView 页面。
4. 切换工作台与管理中心再返回时保留页面状态，不因切换重复创建或刷新 WebView。
5. 页面返回、关闭再打开、加载失败重试均正常，不产生重复 WebView 或残留实例。
6. 会话来源、资源授权、脚本与插件注入规则保持有效。
7. 实际客户端窗口完成视觉及操作验收；构建或接口检查通过不能替代客户端验收。

## 6. 回退与交付

保留旧模块接入方式，记录菜单切换到新模块的具体改动，以便异常时恢复原入口。回退不要求清除现有会话或业务数据。

实施交付应包含独立模块、菜单接入改动、定制入口说明、验证结果及回退说明。当前只保存此方案，不执行开发、部署、提交或推送。
