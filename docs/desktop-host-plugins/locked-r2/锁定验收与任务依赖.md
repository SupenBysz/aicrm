## 5. 宿主不变的 v1 → v2 演示步骤

1. 一次性构建含新宿主与真实开发公钥策略的 Electron，并部署兼容 Web，随后冻结。仓库 `apps/aicrm-desktop/package.json` 未提供安装包发布命令；`scripts/start-dev.mjs` 现有 Mac 开发壳会重写元数据并执行 ad-hoc codesign。因此首轮允许使用**固定且签名验证通过的开发 runtime + 应用 out/package**，不要求为此另建完整安装包流程，不声称验证过 Developer ID、公证或安装包分发。运行时实际签名身份/验证结果由本地记录，不由服务器假定。
2. 生成 `freeze-manifest`：按相对路径排序记录文件 SHA-256、大小；覆盖整个 runtime .app（主执行文件、Helpers、Frameworks、Resources、签名资源/Info.plist）、应用全部 out（含 main/preload/固定 runner/离线页/内置包）、package.json、运行时外置依赖与开发策略等所有会执行/影响加载的资源，以及完整 Web dist 的 HTML/JS/CSS/资源。符号链接记录目标并纳入实际加载目标校验；记录启动参数与应用版本，剔除凭据，仅 userData 更新状态/外部插件包不在冻结集内。若已有真实安装包另记其 hash；没有则标未验证。仅 main/preload 两个入口 hash 相同不够。
3. 使用冻结构建以 preview/固定启动方式运行，不用 HMR/watch 自动改写宿主。安装真实开发 key 签名的 `cn.org.kww.desktop.status-bar@1.0.0`；显示 `v<真实宿主版本>`，记录插件 digest/版本、主进程 PID 与启动时间。宿主版本读取既有 app 版本源，不查 Electron 引擎版本。
4. 发布同 ID `1.1.0`（演示 v2），仅改 title 与版本详情按钮交互，不增加 capabilities/API；由本地同一持久专用 key 独立签名，服务器仅托管公共包/索引。整个更新期不得重新签 runtime、构建 out、同步宿主文件或发布 Web。
5. 必须通过**宿主原生菜单**“检查插件更新”触发固定源更新（不是 Web 按钮、开发控制台或测试 hook）；菜单不接受任意 URL/path，只处理签名发布项。验证候选/drain/ACK/60 秒 stable，实际点击 v2 按钮展开、收起详情。随后通过原生菜单“回滚插件”回到 v1，再验证 v1 行为，主进程 PID 与启动时间全程一致。
6. 在 v1、v2 stable、回滚后三点复算冻结清单，全部 runtime/宿主可执行资源/Web hash 一致；插件版本分别 1.0.0/1.1.0/1.0.0，宿主版本不变，releaseSequence 高水位不回退。签名验证、动作投影、状态 revision 与截图由本地留证，不能只看版本文案。
7. 异常包（签名/兼容/ready 超时）验证与主更新演示分开记录。故障模拟覆盖每个文件持久化边界；Mac 实机至少在 verified、activating 已落盘未完成 UI ACK、probation、stable 已落盘四点强杀主进程，以及候选 renderer 崩溃各一次；用受控测试同步点定位并记录阶段/revision，不能仅凭随机 kill 声称命中。测试同步设施若需要，须在冻结前编入开发构建，正常菜单演示不通过它替代实际流程。
8. 冷启动/断网/强杀恢复可主动重启，须与同 PID 更新演示分组记录；报告每个实测点和未覆盖点。模拟的未 sync 数据丢失不等于实机物理断电，本轮不执行也不声明物理断电验证。断网显示本地页/版本，已有登录持久化不受插件更新影响。
9. 输出只含宿主/插件版本、digest、PID、状态、安全错误码、签名验证布尔结果和文件路径；不得发送数据库配置、服务器密钥、会话值或发布私钥。交付口径为“指定 Mac 开发环境验收”，安装包发布、其他 OS、正式渠道均另列未验证。
