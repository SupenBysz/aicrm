## 本地构建与隔离验收命令

以下在本地 aicrm 仓库根运行，SSH 18180 转发保持建立：

```bash
pnpm --filter @ky/aicrm-desktop install --frozen-lockfile
pnpm --filter @ky/aicrm-desktop typecheck
KWW_DESKTOP_PLUGIN_BUILD=dev pnpm --filter @ky/aicrm-desktop build
node scripts/desktop-plugins/build-isolation.mjs
node scripts/desktop-plugins/run-isolation.mjs
```

最后两条使用独立临时 userData 与合成会话标记，不读取真实 session；程序同步设数据目录和注册协议，ready 后异步启动探针，显式保活，60 秒总体超时，启动器 75 秒超时。只有最终全部 true 且退出 0 才算通过。不要使用 --no-sandbox。上次实测之后产品销毁/存储依赖有修改，冻结前可用这套完整构建再核对一次，不把旧哈希的验收冒充新构建结果。

产品客户端使用固定构建的 preview 模式：

```bash
AICRM_WEB_URL=http://127.0.0.1:18180 AICRM_API_BASE_URL=http://127.0.0.1:18180 pnpm --filter @ky/aicrm-desktop preview --skipBuild
```

开发更新需要构建时 `KWW_DESKTOP_PLUGIN_BUILD=dev`、非打包态和 darwin 同时满足；运行时 AICRM_DESKTOP_DEBUG 不能开启开发信任。普通/正式构建没有开发公钥策略，正式更新关闭。此处验证的是开发 runtime + out，不是安装包/公证/正式发布。

## 原生菜单、v1 与冻结

原生“客户端插件”菜单提供：插件安全状态、检查插件更新、回滚插件、故障验收暂停点、继续暂停点、终止候选渲染进程、重试后台连接。状态对话框与进程标准输出只含真实宿主版本、PID、插件版本、digest、phase、revision、更新启用布尔值，无会话/路径凭据。

1. 固定 Mac runtime .app、全部 out/外置运行依赖/package/开发策略及完整 Web dist hash。停止 watch/HMR，不在演示期间同步代码。
2. 通过原生“检查插件更新”安装 v1，保持至少一个兼容可见可信 UI；等待 prepare/drain/ACK 与 60 秒 probation 后 stable。底栏显示宿主版本；菜单插件版本为 1.0.0，digest 必须等于下文 v1 包摘要。
3. 本地确认 v1 成功后才交接 v2 公共产物；服务器在原 kww 会话重新验签、切换索引，不能普通 SSH 开发。
4. 同一 PID 原生菜单检查更新到 1.1.0，点击版本按钮展开/收起，等待 stable，再原生回滚 1.0.0；复核宿主/Web hash、宿主版本与 PID 不变。

插件启动失败有 20 秒有界降级，主用户窗口不等待插件，底栏可回退原 ClientVersion。无 UI/导航不算 active 崩溃；冷启动/runtime 连续失败及 10 分钟失败窗口可隔离异常包。遇持久恢复阻断不删账本来绕过。
