# 开发签名公钥与策略交接合同

版本：候选 r2，待复核锁定。对应 C05；本文件只定义文档合同，不是已部署配置，不包含密钥实值。关联：[方案](方案.md) §7–8。

## 1. 责任与密钥生命周期

本地当前总协调 AI 是开发签名方，负责先核对专用 key、无冲突时生成并持续保管，再为开发包/索引/策略签名。私钥只在 Mac 工作区外的专用目录，建议 `~/.local/share/kww-desktop-plugin-signing/dev/`，目录 0700、私钥文件 `ed25519-private.pem` 0600、当前用户所有。已有专用 key 先在程序内部核对算法、公钥与指纹，不覆盖、不输出私钥；本地并未在本轮报告实际 key 是否存在，服务器不能声称已检查 Mac 文件。

只传下述公钥 JSON 与公共签名产物给服务器。服务器验证公钥格式/指纹后编入开发专用构建策略，不接收私钥。该 key 同时承担首轮开发域 root/release 签名，靠域分隔和固定权限约束用途；不与业务设备 key、服务器密钥或测试 fixture 共用。正式渠道固定关闭，正式多级根、轮换与多人签名是阶段 5 路线图。开发换 key 需重建宿主，不通过下载目录更新信任根。

## 2. 公钥交接对象 PublicKeyV1

文件建议名 `kww-desktop-plugin-dev-public-key.json`，精确 schema 如下：对象只允许表内字段，全部必填，拒绝重复/未知键。只接受 UTF-8 JSON，文件最多 4KiB。

| 字段 | 类型与校验 |
| --- | --- |
| schemaVersion | 整数，固定 1 |
| purpose | 字符串，固定 `kww-desktop-plugin-signing` |
| channel | 字符串，固定 `dev` |
| algorithm | 字符串，固定 `Ed25519` |
| publicKeyFormat | 字符串，固定 `raw-ed25519-base64` |
| publicKey | RFC 4648 标准 base64、规范 padding、无空白，解码为恰好 32 字节 Ed25519 原始公钥；不接受 PEM/SPKI/JWK 文本混入此字段 |
| fingerprint | 字符串 `sha256:` 加对上述原始 32 字节做 SHA-256 得到的 64 位小写十六进制；不是对 base64 或 PEM 文本取 hash |
| keyId | 必须与 fingerprint 完全相同；不接受任意人工别名 |

本地从专用 PKCS#8 私钥在内存中派生公钥，导出原始 32 字节，计算 fingerprint/keyId。服务器重新解码计算比对，并通过 Ed25519 验证签名向量核查与签名者一致；只交付公钥文件本身不证明持有私钥。公共产物可安全存入源码，私钥路径不得写入宿主运行配置。

## 3. 宿主内置 DevBuildPolicyV1

在宿主构建时由服务器使用已交接公钥生成，目标源码位置拟为 `apps/aicrm-desktop/resources/desktop-plugin-dev-policy.json`。它随冻结宿主发布，不能从 Web、环境或下载目录覆盖。对象只允许以下必填字段：

| 字段 | 类型与固定值 |
| --- | --- |
| schemaVersion | 整数 1 |
| kind | `desktop-plugin-build-policy` |
| channel | `dev` |
| enabled | 布尔 true；仅开发构建可装入该对象 |
| productionEnabled | 布尔 false |
| updateBaseUrl | 精确字符串 `http://127.0.0.1:18180/desktop-plugin-releases/dev/` |
| allowLoopbackHttp | 布尔 true，且仅对上述完整 origin/path 生效，不泛化为 localhost/任意回环端口 |
| publicKey | 完整 PublicKeyV1 对象 |
| pluginId | `cn.org.kww.desktop.status-bar` |
| capabilities | 无重复、顺序固定的数组：`host.app.version.read`、`host.ui.statusBar.publish`、`host.ui.statusBar.action`、`host.runtime.lifecycle` |
| platforms | 数组，恰好 `["darwin"]`；不隐式扩展到 Linux/Windows |
| policyFile | `policy.json` |
| indexFile | `index.json` |

正式构建不装载该开发对象，插件在线更新 enabled=false，也无开发菜单。首轮不生成可启用正式源的策略。测试 fixture 必须走测试依赖注入，不能因文件名、debug 开关或空公钥进入真实开发构建。

## 4. 签名策略与公共分发产物

固定目录内文件：`policy.json`、`index.json`、`<完整包sha256>.kwwplugin.json`。服务器只静态托管这些已签名公共文件，不执行签名、不提供任意上传/运行/安装 API。服务端实际静态映射路径在部署时记录，客户端 URL 始终以上述回环源为唯一来源。

policy.json 的外壳 SignedPolicyV1 精确字段为 `{schemaVersion:1,keyId:string,signedMetadata:string,signature:string}`，无额外字段。keyId 必须等于内置 keyId；signedMetadata 是规范标准 base64 的 UTF-8 JSON 原始字节；signature 是标准 base64 编码的 64 字节 Ed25519 签名。签名输入精确为 UTF-8 `kww-desktop-plugin-policy:v1` + 一个 LF 字节（0x0a）+ 解码后的 signedMetadata 原始字节，不含 BOM，不是字符反斜杠和 n，不重排 JSON 后验签。

signedMetadata 解码得到 PolicyPayloadV1，所有字段必填且无额外字段：

| 字段 | 类型与校验 |
| --- | --- |
| schemaVersion | 整数 1 |
| kind | `desktop-plugin-trust-policy` |
| policyVersion | 正安全整数 1..9007199254740991；相同版本必须相同已签名 payload 摘要 |
| channel | `dev` |
| keyId | 等于内置 keyId，不支持在此替换/添加公钥 |
| pluginId | 等于内置 pluginId |
| capabilities | 无重复字符串数组，必须是内置能力集合的子集，不能扩大 |
| notBefore、expiresAt | UTC 字符串 `YYYY-MM-DDTHH:mm:ssZ`，真实合法时间且 notBefore < expiresAt；安装新包时当前时间位于该区间 |
| revokedPackageDigests | 无重复小写 64 位 SHA-256 字符串数组，最多 128 项；当前 policy 中已知吊销累计生效，旧 policy 不能撤回 |

首次 policyVersion=1；重复下载同一已签名 payload 可幂等。拒绝更低版本、同版本异 payload；新版本若删除已知吊销项也拒绝。高水位与已接受 policy 的不可变授权证据关联，丢失证据进入阻断恢复。开发 key 失陷时必须更换宿主策略，不能要求失陷 key 自证可信。

index.json 外壳同上，签名域换成 `kww-desktop-plugin-index:v1` + LF。首期索引仅一发布项，payload 精确字段为：`schemaVersion:1`、`kind:"desktop-plugin-release-index"`、`channel:"dev"`、`pluginId`、`policyVersion`、`releaseSequence`、`version`、`packageSha256`、`packageBytes`、`fileName`、`expiresAt`。其中 releaseSequence 为正安全整数；version 为严格 SemVer；packageSha256 为 64 位小写 hash；packageBytes 为 1..2097152 整数；fileName 必须等于 packageSha256 + `.kwwplugin.json`；expiresAt 为上述 UTC 格式，新安装须未过期且不晚于 policy expiresAt。其余字段与当前 policy/manifest 一致。索引不含任意 URL、公钥、凭据或路径。全部签名对象执行方案中的字节/深度/重复键限制。

包外壳精确为 `{schemaVersion:1,keyId,signedMetadata,signature,files}`，签名域 `kww-desktop-plugin:v1` + LF；metadata 含 manifest 与带 path/size/sha256 的签名文件清单，具体约束见方案 §8。包签名者必须与当前 policy keyId 相同。公钥交接、内置策略与 policy/index 的签名 golden vectors 在 D1/D4 验证；本文件中的类型说明不当作真实可安装产物。

## 5. 交接出口

本地提供真实公钥对象、指纹、使用该 key 签名的 policy 与测试公共向量；服务器确认字段/摘要/验签一致再纳入开发构建。公钥实值应在 D6 冻结宿主之前到位；测试 fixture 可先做单元测试，但不能替代真实开发发布验收。通过后同一持久开发私钥继续签 v1/v2，更新期不换公钥、不改宿主策略。
