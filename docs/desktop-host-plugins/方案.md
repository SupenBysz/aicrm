## 1. 目标与首轮边界

在客户端已经提供的本地能力和 UI 协议范围内，通过更新签名插件包更新本地功能与交互，不再重装客户端。首次引入插件宿主、安全桥与 UI 槽必须更新一次 Electron 宿主构建并部署一次兼容 Web（开发环境可用固定已签名 runtime + 应用构建；有安装包流程时再验证安装包）；之后用同一个宿主构建完成状态栏插件 v1 → v2 → 回滚演示。不能承诺新增原生能力、修复 Electron 安全漏洞或改变协议主版本也无需更新安装包。

首轮锁定范围为阶段 1–3：真实盘点与协议边界；最小宿主及状态栏试点；独立签名更新、兼容、原子切换、恢复与回滚。阶段 4 逐步迁移低风险本地功能，阶段 5 管理页与发布治理仅进入路线图。账号、Vault、设备证明、授权、执行器和全局登录/工作区策略不迁移。没有数据库迁移、角色、服务端插件运行时或执行器 readyz 依赖。

## 4. 隔离执行与能力模型

选择独立隐藏 sandboxed BrowserWindow 运行每个候选/活动插件的纯浏览器 JS。主窗口和插件不共享 webContents、session partition 或 preload；插件窗口 show=false、禁止弹窗/导航/下载/权限请求，contextIsolation=true、sandbox=true、nodeIntegration=false、webSecurity=true，禁用 webview、Node worker 与开发绕过开关。插件入口使用宿主注册的 `kww-plugin:` 本地协议；主进程仅按已验证实例映射读取包文件，绝不接受原始路径参数。

固定启动页和 preload 随宿主安装；只有验签并入库的 JS 文件在插件 renderer 中执行。协议只允许本实例的 digest/路径，CSP 限制 script-src 到本包、connect-src/object-src/frame-src/worker-src 为 none，不允许 eval、内联脚本、远程 import。专属 session 拦截网络请求和权限 check/request；禁止 service worker、跨包/跨协议资源。JS 只能通过固定插件 SDK 使用下表能力。禁止把远程包 main require/import、Node vm、普通 Node 子进程或 utilityProcess 当安全沙箱。沙箱也不提供抵抗 Electron/OS 漏洞或同一 OS 用户完全失陷的保证。

阶段 2–3 最多一活动实例加一候选实例；插件 CPU 卡死由宿主墙钟 watchdog 杀掉插件 renderer 并恢复旧包。后台节流需显式控制并在 Mac 验证；资源限制以包/消息/实例上限和超时为硬约束，不把 JS 堆参数当 OS 内存配额。

| 能力 | 类型 | 阶段 1–3 授权 |
| --- | --- | --- |
| `host.app.version.read` | Query | 返回与 app:get-version 相同的客户端版本字符串；不返回路径、环境、Electron 版本 |
| `host.ui.statusBar.publish` | Command | 提交结构化状态栏投影，宿主校验并持有最终渲染权 |
| `host.ui.statusBar.action` | Native Event | 宿主将本槽白名单动作发送给当前实例；只触发插件本地展示状态 |
| `host.runtime.lifecycle` | 协议内生命周期 | hello、prepare、activate、drain、heartbeat；不能授权其他能力 |
| 文件、网络、剪贴板、进程、窗口管理、session、Vault、设备密钥、账号、执行器、业务 API、更新安装 | 不提供 | 一律拒绝，manifest 请求未知能力也拒绝 |

有效权限 = 宿主支持集合 ∩ 本地安装策略 ∩ 有效签名授权的能力集合 ∩ manifest 声明。插件签名证明来源，不能自动授予 manifest 中的所有权限。阶段 3 只授权上述单一插件 ID 和固定能力集；新增 ID/扩大权限需要新的宿主策略审批，不由更新目录自助提升。

Main 根据自行登记的 webContents、主 frame、固定协议 origin、pluginId、digest、instanceId、epoch 识别调用方，不能信任请求自报 pluginId。专用 handler 验证 schema、长度、频率和状态。所有既有 IPC 对插件 sender 默认拒绝，补充通用 sender gate 并保留现有受控窗口所需白名单回归；不能大范围改动账号协议。插件 preload 不暴露 ipcRenderer，也不提供任意 method/channel 转发。

### 4.1 全入口 sender gate（C04）

实施采用唯一 `GuardedIpcRegistrar` 注册器：只有该模块可导入真实 ipcMain 并注册 handle/handleOnce/on/once/addListener；全部既有 `main/ipc/*.ts`、注入式 IPC 注册函数及未来模块改为接收该受限接口。不得另用 webContents.ipc/frame 级 IPC 注册绕过该入口；如既有代码存在这些入口，同样纳入注册器适配与枚举。注册必须提供 channel、明确 roles、输入 schema 与 handler；未声明角色或重复占用 channel 时启动失败，不存在默认放行。每个物理 channel 只注册一个受控分发器；同 channel 的每个逻辑监听器调用前都独立校验。不得靠前置监听器 throw、stopPropagation 或隐藏 preload 阻止其他监听器；被拒绝的 on 消息直接安全返回，不执行任何业务 listener，handle 返回约定安全失败。

宿主窗口工厂在加载内容之前按 webContents 对象登记角色：主后台、受控账号窗口、授权窗口、终端窗口、内置离线页、插件候选/活动实例。逐 channel 白名单按既有实际调用盘点，受控窗口不自动继承主后台所有权限；子 frame、未知 sender、空 senderFrame、非当前 mainFrame、失效导航代次一律拒绝。每次调用重新核对当前角色、frame、允许的 origin/文档代次与实例 epoch；不能只校验注册时 URL。导航开始立即撤销旧文档授权，可信导航提交后由工厂明确建立新代次，不由页面自报角色恢复。

`destroyed`、`render-process-gone`、窗口关闭/实例替换时删除注册记录、UI 会话、pending request、计时器与订阅；迟到异步回包在发送前复核代次，禁止投送新文档。main 退出销毁插件实例及注册器，下一启动重新登记，不持久化 webContents ID 授权。

可测试门禁：AST/导入扫描禁止注册器之外直接注册、别名导入或传递原始 ipcMain；按运行注册表枚举所有 handle/on 通道逐个测未知 sender、插件 sender、同源子 frame、已销毁 sender 与合法角色。`window-ipc.ts` 的 windowMoveBy 使用 on，必须列入；注入式 device binding handler 也必须经过同一注册器。测试同 channel 两个逻辑 listener 时拒绝调用的副作用计数均为零；测试未来新增通道不带 roles 注册失败。扫描约束用于防止遗漏，真实 Electron 分帧测试与既有角色回归才证明运行效果。

权限是本地能力授权，不是业务 RBAC；插件不读取 actor/token/workspace。任何未来租户副作用仍须既有服务端 actor/grant/ticket/proof 合同，不能用包签名替代。试点不接触这类能力。

## 5. UI 槽、真实版本与 Web 兼容

首期只开放 `statusBar.right`，投影 UI schema 1.0.0：至多 4 项，类型仅 `text`、`button`；稳定 itemId，text 至多 80 字符、title 至多 160 字符，tone 仅 muted/normal；button 的 actionId 必须在 manifest 中声明。禁止 HTML、Markdown、URL、style/className、脚本、表单、图片和动态组件导入。Web 使用 React 文本转义和宿主内置组件；原生窗口边框、全局布局、登录页与工作区选择依然由各宿主负责。

底栏保留 28px、右对齐、明暗主题 token、窄屏省略和完整 title；只能消费其布局槽，不覆盖内容。试点默认仅显示动态 `v0.1.0`，去除重复 v；title 可完整说明。宿主版本来自现有 package 版本源，插件 version 来自验签 manifest，只在本地诊断/验收中独立报告，不混到“客户端版本”。v2 可仅改 title 和点击后展开/收起的本地版本详情，演示已有 button 协议内交互更新，不扩展原生权限。

所有插件投影经 Main 校验后，通过既有 `window.aicrm` 新增 `desktopPlugins` 命名空间发往可信 Web，再由专用 adapter 转成槽数据；不往 Web 下发 JS。Web 只订阅一个宿主状态源，按 epoch/sequence 维护派生状态并释放订阅。插件投影成功与 Web 完成渲染是不同握手。

| 组合 | 行为 |
| --- | --- |
| 新宿主 + 支持槽协议的新 Web | Web 注册 uiApiVersion=1.0.0 与槽集合；候选只在能力交集内启用，活动 epoch 在所有可见已注册窗口一致切换 |
| 旧宿主 + 新 Web | 无 desktopPlugins 能力时继续既有 ClientVersion 降级；不错误调用新桥 |
| 新宿主 + 旧 Web | 未注册槽，不激活新候选；保留已验证包和原显示，不注入任意 DOM 或重复底栏 |
| 普通浏览器 + 新 Web | 不加载本地插件，不显示客户端底栏 |
| Web 热更新失去兼容槽 | 隐藏插件投影并降级，不破坏 session；插件暂停 UI 工作，重新握手后恢复 |
| Web 离线/无法加载 | 已验证插件可本地启动并停在等待 UI 状态；没有兼容 UI 时禁止候选成为 active |

宿主附带最小本地离线页与同协议状态栏 renderer，只有远程 Web 加载失败时由 main 显式展示；不伪造 CRM 登录成功，不缓存业务页面或 token。离线页提供“网络不可用/重试”和宿主版本，使断网时插件状态栏仍可验证。离线页与远程 Web 都必须完成 uiApiVersion 握手。本地协调方已接受最小离线页，不能据此声称远程后台已具备离线运行。

### 5.1 可见 UI 会话与非空确认规则（C02）

Main 登记 `(webContents, mainFrame, navigationGeneration)`，可信文档完成 registerUi 后签发随机 uiSessionId；同文档重复注册幂等，重载必须换代。uiApi/槽兼容且原生窗口可见、未最小化、文档已完成可信导航，才进入 required 集合。renderer 自报 visible 不算凭据。导航开始、刷新、frame 销毁、窗口隐藏/最小化、render-process-gone、显式 unregisterUi 均立即移除该会话并撤销旧 ACK；事件缺失另由宿主检查窗口/frame 存活性兜底。

每次集合变化递增 uiMembershipRevision；所有 ACK 绑定 uiSessionId、navigationGeneration、uiMembershipRevision、activeRevision、candidate digest 及此次宿主 challenge。集合变化后向当前集合重新发快照/challenge，旧会话/旧集合 ACK 不能复用。提交 probation 和 stable 的条件都为 **required.size >= 1 且当前集合全部 ACK 有效**，并在状态写入前同一串行状态机再次校验；不得使用 every([]) 或历史上曾存在 UI 来替代。磁盘写入期间若集合变化，提交后立即按丢失 UI 路径收敛，不将跨进程状态虚称原子。

- preparing/draining 之前没有兼容可见 UI：候选停在 verified，等待原因 waiting_ui；不计候选故障，正常 active 进入仅暂停 UI action 的 waiting_ui 运行态，保留版本与进程心跳。UI 缺席不是 active 心跳失败。
- draining 中集合变空或发生导航：解除旧 active 的 drain，候选退 verified/waiting_ui；UI 恢复后重新准备并排空，不能沿用旧 ACK。
- activating/probation 中集合变空，或 required 中有会话重载/加入导致失去完整确认：撤销候选活动权限，恢复 previousStable，保留候选 verified/waiting_ui，停止本轮观察计时；不因正常 UI 导航隔离包。恢复 UI 后重新激活并完整观察 60 秒，禁止累计无人见证的观察时间。
- 可见可信会话持续存在但未按时 ACK/投影不合法属于 UI 验收失败，回旧稳定包并记录原因，候选可隔离；与窗口主动隐藏/导航分开计数。正常 active 无 UI 时不要求 ackRendered，也不因 Web 未登录/重载而被 watchdog 杀掉。
- 新窗口、重载页面或离线页按新会话注册；stable 状态只给它当前快照，不引起插件更新。切换过程中新注册窗口必须参与新集合确认，不能仅让旧窗口的确认放行。

## 6. manifest、API 和消息合同

候选 manifest 必填字段：`schemaVersion:1`、`kind:"desktop-host-plugin"`、`id`、`version`、`entry`、`engines.host`、`engines.pluginApi`、`engines.uiApi`、`platforms`、`capabilities`、`contributes`、`data:{mode:"none",schemaVersion:0}`。插件版本为严格 SemVer，禁止用包名或文件名推断。首期无依赖插件、无安装脚本、无原生二进制、无数据迁移脚本。

示例版本约束：host `>=0.1.0 <0.2.0`、pluginApi `>=1.0.0 <2.0.0`、uiApi `>=1.0.0 <2.0.0`，还须实际能力探测，版本号相同的旧客户端不因范围匹配而被当作新宿主。支持标准 SemVer 的明确上下界 AND 范围，禁止 *、无上界、URL/Git 版本、隐式 prerelease；schemaVersion 未知直接拒绝。host/application、plugin、pluginApi、uiApi 是四个独立版本，不能复用业务 Bridge v2 标记。首轮验收平台 macOS；Linux/Windows 需分别完成 sandbox/文件原子性验收后才能进入支持列表。

物理 channel 统一登记到 `IPC_CHANNELS`，建议域 `desktop-plugins:*`，固定白名单方法：Web 侧 registerUi/unregisterUi/getSnapshot/onChanged/ackRendered；插件侧 getHostVersion/publishStatusBar/hello/ready/heartbeat/ackDrained/ackAction/onLifecycle/onAction。更新检查/安装/回滚不暴露给普通 Web 或插件。

请求包含 requestId 与有界 payload；实例身份由 Main 注入。结果采用既有 DesktopCommandResult 风格的可判别成功/错误联合，code 包括 permission_denied、validation_error、conflict、plugin_incompatible、plugin_timeout、plugin_quarantined、plugin_storage_unsafe。每个失败对 UI 返回中文安全说明，不返回路径、URL 凭据或原始堆栈。

非持久事件包含 id/name/version/source/scope/occurredAt/correlationId，以及 operationId、runtimeEpoch、nativeSequence、activeRevision。先订阅缓冲，再读取带序号的 snapshot，丢弃旧 epoch/重复序号；gap/overflow 重新取 snapshot。Main 每次实例切换撤销旧能力映射，旧实例迟到消息无法生效。onXxx 返回 unsubscribe，Host effect cleanup 释放 listener/timer；每消息最多 16KiB、每实例每秒最多 20 条、最多 8 个进行中 Query；UI 发布最多每秒 5 次。超限拒绝，持续异常隔离实例。

## 7. 签名、更新来源与安全存储

选择 Ed25519 + SHA-256，包格式 `kww-desktop-plugin` 版本 1，独立于 Electron 自动更新。客户端只内置公钥，不持有发布私钥；不复用登录、设备证明、AI 或服务器内部服务密钥。

首轮仅启用开发渠道，正式渠道 disabled，正式根轮换/多人发布留在阶段 5。开发构建固定一把独立 Ed25519 公钥，作为该开发信任域的 root/release key（同一把专用开发密钥，不复用业务/测试密钥）；其签名 policy、索引和包用不同域前缀区分。首轮不实现动态换根，新 key 必须重新构建宿主。后续正式方案再锁定独立 root/release 分工和旧新根双签轮换，不暗示当前已实现正式发布管理。

本地当前总协调 AI 负责核对、生成、保管及签名。私钥持久保存在 Mac 工作区外专用目录，建议 `~/.local/share/kww-desktop-plugin-signing/dev/`（0700）、`ed25519-private.pem`（0600、PKCS#8）；用于后续开发发布，不要求每次删除。生成前只在该专用目录核对已有文件的所有者/权限/算法，并在程序内部派生公钥比对既有专用公钥/指纹，不打印私钥，不覆盖已存在 key；不搜索其他项目密钥。若现有 key 用途或公钥冲突不明，报告冲突再处理。只有公钥交接 JSON、指纹与签名公共产物传给服务器，私钥不进仓库/服务器/日志/客户端；临时私钥副本若产生应删除，持久原件保留。服务器不代生成签名身份，fixture 仅用于测试。

公钥与策略的精确合同见 [开发签名配置](开发签名配置.md)。本轮不生成或读取密钥。未来下载凭据若需要仍由 main 使用独立 safeStorage 密文，拒绝不可用或 basic_text，不借用 CRM token；首轮固定源无需凭据。

发布目录由 release key 签名，绑定 pluginId/channel、单调 releaseSequence、version、完整包 sha256/字节数、相对文件名、policyVersion、expiresAt；只从固定本地安装策略的 base URL 拼接。过期目录不得安装新包；本地保存最高已接受序号和 policyVersion，拒绝旧目录回放和同序号异内容。失败新版本不能自动重复尝试，必须有新 releaseSequence 或明确本地管理员重试。正常自动回滚仅到先前记录的 lastKnownGood，不降低已见最高发布序号。离线不可能即时获得吊销信息：已缓存且未被已知吊销的活动包继续工作，联网收到有效新吊销后停用，不声称实时撤销。安装时持久保存通过验证的授权 policy 与索引证据；启动验签复核使用该安装授权证据和当前已知吊销集，release key 的后续自然到期不等于撤销旧包，不能因每次套用“新安装有效期”破坏离线启动。时钟明显回退时禁止新安装，不能因此放过过期目录。

生产仅 HTTPS、固定 origin/端口/路径前缀、正常 TLS 校验、禁止 userinfo/query 凭据、重定向一律拒绝。开发演示固定 `http://127.0.0.1:18180/desktop-plugin-releases/dev/` 经现有 SSH 转发，必须由宿主开发策略显式允许，不能因任意 debug 参数放开 HTTP/来源；正式构建不接受该例外。拒绝外部 URL、协议相对路径、绝对路径、DNS/跨源重定向；下载完全在 main，插件没有网络。

下载连接超时 5 秒、总超时 30 秒；目录/trust policy 各不超过 64KiB，包最多 2MiB，校验声明大小和实际流字节上限，不信任 Content-Length。请求 Accept-Encoding: identity，拒绝压缩响应；不跟随 Range/断点残留，不覆盖 active。网络失败退避且保留旧包。

## 8. 包格式与可信目录

为减少首轮解包攻击面，采用无压缩 JSON 文件集合，不支持 tar/zip/安装脚本。外层仅包含格式版本、keyId、signedMetadata（base64）、signature、files；签名内容为固定域前缀 `kww-desktop-plugin:v1\n` 加 signedMetadata 的原始解码字节。签名前后使用同一字节序列，不依赖 JSON 字段排序。元数据含完整 manifest 与文件列表，每项 path/size/sha256；files 只含 path/contentBase64。严格拒绝重复 JSON 键、重复路径、未知顶层字段、无效 UTF-8/非规范 base64、额外文件、缺失文件和哈希不符；先验证元数据签名，再使用元数据授权内容。外层解析前先限制总字节；带深度上限 16 的严格解析器必须拒绝重复键，普通 JSON.parse 单独使用不满足该约束。目录签名采用不同域前缀 `kww-desktop-plugin-index:v1\n`，trust policy 使用 `kww-desktop-plugin-policy:v1\n` 前缀；索引和 policy 同样使用精确字节的 signedMetadata/signature 外壳并拒绝重复键，禁止跨类型重放。

最多 16 个文件，单个解码后 512KiB、总计 1MiB；仅允许 .js/.json 和最多两级目录。路径限定 ASCII 小写字母/数字/短横线/下划线/点与分隔符，路径段不得为空、.、..、隐藏名、Windows 保留设备名；拒绝反斜杠、冒号、百分号、NUL、绝对路径、Unicode/大小写折叠冲突。无归档条目意味着没有软链接/硬链接/设备节点格式，但落盘仍须检测真实目录链中的软链接、所有者、权限和文件类型。不能仅用字符串 startsWith 判断包含关系。

运行根 `app.getPath("userData")/desktop-host-plugins/`：Unix 0700、普通文件 0600，仅当前 OS 用户拥有；Windows 需要单独 ACL 验收。本机同用户恶意进程或管理员拥有修改能力是威胁边界，不把 0600 说成对同用户的隔离。分开 `staging/<operationId>`、`packages/<id>/<digest>`、`state/`、`quarantine/`；不扫描 Downloads、仓库目录或环境指定目录加载。代码目录不接受插件写入，不支持“放进去就自动加载”。

宿主新建随机 staging，以 exclusive/no-follow 打开普通文件、验证父链与 realpath containment；仅按签名文件集合落盘。校验完 sync 文件和目录，在同一文件系统 rename 到不可变 digest 目录。已有 digest 必须重新验证一致才可复用。每次启动重新验签和校验文件 hash；协议读取打开文件后复查类型/大小/hash 再返回字节，防止验证后换包。可信目录的含义是验证过的包、明确授权、受控所有者和状态引用同时成立，不是“路径看起来可信”。

## 9. 候选验证、启用与原子恢复

Main 是唯一状态写者，用既有单实例锁加插件存储独占锁；同插件仅一个更新事务。唯一权威状态文件为 `state/host-state.json`，schemaVersion=1，字段定义如下；其他快照/备份不是并列状态源。

| 字段 | 精确含义 |
| --- | --- |
| schemaVersion、revision、pluginId、phase、operationId | 固定版本 1；非负安全整数 CAS revision；授权 ID；阶段枚举；空闲时 operationId=null |
| active、lastKnownGood、rollbackTarget、candidate、previousStable | 每项 null 或 PackageRef={digest,version,authorizationDigest}，digest 为小写 SHA-256；previousStable 为当前事务开始时 lastKnownGood，在试运行期间不可改变/清理 |
| activeRevision、data | 单调投影 revision；固定 {mode:"none",schemaVersion:0} |
| recovery | {updatesBlocked:boolean,reason:null或安全错误码}；为 true 时禁止更新检查结果进入安装/激活 |
| highWater | {policyVersion,policyDigest,releaseSequence,indexDigest}；版本/序号为非负安全整数，初始 0/null；同序号必须同 digest |
| bootLedger | 最多 32 个包 digest 记录（GC 不得删除活动/回滚/事务引用包的记录）：{attemptId,startedAt,initializedAt,consecutiveFailures,failureTimes,lastFailureCode}；failureTimes 仅保留最近 10 分钟最多 3 次，连续计数到 3 封顶；pending attempt 在下一启动只结算一次 |
| failures、waitingReason | 有界候选失败摘要（最多 32 项，含 operationId/digest/code/时间）；waitingReason=null或 waiting_ui/drain_busy |

阶段为 stable/downloading/verified/preparing/draining/activating/probation/quarantined。启动时 active=lastKnownGood=内置包、rollbackTarget/candidate/previousStable=null。事务开始时 previousStable=lastKnownGood；probation 中 active 可为候选，但 lastKnownGood 与 previousStable 固定为旧稳定包，rollbackTarget 仍保留上次回滚目标。stable 提交时一次写入 rollbackTarget=previousStable、active=lastKnownGood=candidate、candidate=previousStable=null。失败恢复 active=lastKnownGood=previousStable；显式 stable 回滚仅选 rollbackTarget，先验证授权/兼容，再把原 active 保存为 rollbackTarget，不变更 highWater。bootLedger 失败计数不随包回滚清空。

所有状态用 expectedRevision CAS，写临时文件 → file sync → rename → parent directory sync；同一文件系统。最高已接受 policy/目录序号和摘要在任何候选处理前先持久化；即使后续下载/启用失败也不回退。相同序号/摘要可重试同一包，相同序号不同摘要或更低序号拒绝。日志只输出安全 ID/digest/阶段，摘要用于损坏检测，不是防攻击签名。

**恢复选择（C03）：不自动恢复较旧 state 备份来继续更新。** 上一有效副本仅作诊断。主状态缺失/损坏/schema 无效/与诊断副本关系无法解释时，先以独占写创建并 sync `state/recovery-blocked` 标记，再仅启用内置基线；即使读取备份用于诊断，也不得将其 highWater 当最新值。该标记一旦存在，任何有效/旧备份恢复都不能解禁；无法持久写标记则本次进程直接拒绝一切外部包更新。不存在状态且存在安装/状态目录历史痕迹同样阻断，只有从未初始化的全新根才可创建零高水位。首次初始化先落初始化标记，再写状态，中途断电按阻断处理。

r2 首轮不提供清除 recovery-blocked 或“重置版本”菜单；不能靠删文件、重装宿主、旧备份或回滚包解禁。人工恢复需另有可信高水位恢复合同，本轮保持阻断。正常 intact 主状态恢复严格使用其 highWater，所有分支只增加不降低。主动同用户删除/回放整个 userData 超出本机文件完整性威胁模型，不宣称仅靠文件校验能抵抗。

1. 候选包验签、平台/四版本/能力/UI/data 合同静态验证通过后落入 verified。
2. 新实例获得独立 instanceId/epoch/随机 challenge。5 秒内 hello 必须回显 challenge、manifest digest 与 API 版本；Main 再核对真实 sender。候选只可读取宿主版本并向缓冲槽发布，不影响活动 UI。
3. 10 秒内候选给出合法初始投影、ready；宿主实际验证响应和投影，不相信一句 ready=true。没有兼容可见可信 UI 时按 §5.1 停在 verified/waiting_ui，不消耗启用超时。
4. 暂停旧实例新 action/intake，Main 等进行中 Query/action 计数清零，并发送 drain。每次宿主分发 action 都创建 action requestId，插件必须返回完成 ACK；候选无权接受用户 action。计数只随对应完成/取消记录减少，不能收到任意 ACK 就归零。30 秒内必须 ackDrained 且宿主计数为零；插件自报 busy=false 不能替代计数。超时保留旧 active、丢弃候选，不强杀正在执行的业务任务。试点没有业务任务，也不触碰全局 Codex quit fence。
5. 持久化 activating（含旧 active 和候选），隔离旧实例发送权限；发送 activate 给候选，5 秒内等待 ACK 和首个有效投影，然后以递增 activeRevision 切换内存投影，向所有当前已注册可见 UI 发送快照。每个 UI 在 5 秒内回报 ackRendered，包含 UI 会话、revision、digest。候选不知 Web 凭据；Web ACK 只是渲染存活证据，不是包授权依据。
6. required 非空且当前会话/集合/revision/digest/challenge 全部确认才持久化 probation；注册/注销、导航和集合变空严格按 §5.1 延期或回退，不以空集合成功提交。协议或插件失败隔离候选；正常 UI 消失仅延期。旧实例在 probation 保持冻结，previousStable 包引用保留至 stable 提交，确认稳定后销毁旧实例。
7. 观察 60 秒，每 2 秒心跳、连续 3 次缺失或 render-process-gone 判失败；同时持续满足 §5.1 非空 UI 确认条件，通过才按本节唯一 schema 原子持久化 stable，并使候选成为 lastKnownGood，保留前一稳定包为 rollbackTarget。未提交 stable 不清理旧包。

磁盘提交与多窗口画面不可能成为一笔跨进程 ACID 事务；保证的是磁盘选择原子、活动授权单一、带 revision 的投影不混用、失败可恢复。ACK 后到落盘之间崩溃允许回到旧包，不能承诺用户绝未短暂看到候选。

| 故障点 | 下次启动确定行为 |
| --- | --- |
| 下载/落盘未完成 | 保持旧 stable；无状态引用 staging 可清理 |
| verified/preparing/draining | 放弃未生效候选，启动旧 active；必要时解除旧 drain |
| activating/probation 断电或 main 崩溃 | 候选标记未完成，回到记录的旧稳定包；不根据新文件时间猜 active |
| stable 持久化后崩溃 | 重新验签 stable 包；启动前持久化 attempt 标记，原生插件初始化通过后结算成功（不等待 Web UI）；UI 缺席不计启动失败。pending attempt 遇下一次启动计一次失败，时钟回退不清除连续失败次数 |
| 活动实例持续启动失败 | 每次启动失败持久计数；同 digest 连续 3 次或 10 分钟内 3 次失败隔离并回退可信 rollbackTarget，再失败回内置基线，禁止无限重启 |
| 状态损坏/权限不安全/活动包 hash 错误 | 停用外部包并保留诊断；状态无法证明时持久阻断更新并用内置基线，禁止旧备份降低高水位；不遍历目录挑最新版 |
| 回滚包已被吊销或不兼容 | 不回滚该包，退内置基线，等待修复包或宿主升级 |

包回退不改变宿主或 Web 版本，不回写 CRM/账号数据库。

## 10. 数据、排空、清理与离线边界

首期 data.mode=none，插件没有持久存储 API；只有宿主更新账本、授权策略和运行诊断持久化。因此状态栏 v1/v2 回滚不涉及业务数据。任意包声明迁移/持久数据模式立即拒绝，不能静默忽略。未来插件数据方案须独立锁定 read/write schema range、快照、配额和单写者；破坏性迁移完成后禁止旧包直接读取或恢复旧写者，只能兼容升级/forward-fix。包能回滚不等于数据能回滚。

未来长任务只能经过宿主登记 lease，停 intake 后等待真正结束；无法安全排空则延期切换，不能在插件升级时中断账号或 AI 工作。此次不会包装已有账号/执行器任务为插件任务。

清理只由宿主做：stable 后至少保留当前包、上一稳定包、内置基线及所有运行实例/事务引用包；无引用旧包保留 7 天后删。最多保留额外 3 个成功历史包；容量预算 32MiB，达到预算且不能安全清理时拒绝新更新，不能删除回滚依据。失败包只保留有界安全诊断，内容隔离且无执行入口；staging 超过 24 小时且无活跃锁可清理。GC 从已验证状态的引用集合计算、复核真实路径/所有者/锁，绝不递归删 userData 根。进程退出未确认的包不得清理。

离线启动不等待网络：先恢复本地状态和可信包，再异步检查更新。索引过期只阻止新安装，已验签的稳定包可离线运行；已知吊销仍生效。Web 离线走本地最小页，业务操作不可用。首次离线且无外部包时使用随宿主发布的内置状态栏插件基线；内置包 digest/manifest 随宿主固定，不来自可写下载目录。

## 11. 阶段路线图与需要共同接受的选择

阶段 1 输出协议、威胁模型、兼容矩阵和失败状态机，交叉复审通过后才锁定。阶段 2 实现宿主、sender gate、内置状态栏与 UI 槽；阶段 3 在相同宿主上完成独立签名包更新/回滚/离线/故障验收，才称首轮闭环。阶段 4 候选是本地展示偏好、帮助信息等低风险功能，逐个过四项 Skill 闸口；阶段 5 才建设管理页、分发授权、灰度、审计、多人签名和发布治理。

## 12. 外部技术依据与验证限制
