# 运行时依赖与验收

## 已验证

准确目标基线依序应用既有窗口三层和菜单核心三层；服务器干净副本完成58项前端合同/行为测试、Membership全包Go测试、Core/脚本管理/权限插件构建、权限插件类型检查、Host类型检查及构建，gofmt与diff检查通过。脚本管理声明产物需在同一副本构建，不借用其他工作树的workspace链接。

本地另外独立验证六层补丁顺序应用、反向恢复。最新源码参考在339b0af提交上完成应用检查、实际应用与反向检查，但不代表它可直接叠加到9ecddf2核心组合。对应WebView功能此前在KWW客户端有运行验收，不能将该证据当作本目标补丁已完成实机验收。

建议构建顺序：

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @ky/admin-core build
corepack pnpm --filter @ky/plugin-script-management build
corepack pnpm --filter @ky/plugin-access-management typecheck
corepack pnpm --filter @ky/plugin-access-management build
corepack pnpm --filter @ky/admin-host typecheck
corepack pnpm --filter @ky/admin-host build
go test ./services/ky-membership-service/...
```

Node测试含TypeScript模块，可采用验证时的tsx执行器；测试文件列表以核心补丁文件清单和验证记录为准。PostgreSQL集成测试需隔离数据库，不向业务库运行测试。服务器未构建或启动Electron；目标桌面构建和实机操作仍需在支持环境进行。

## 迁移与发布

确认基线及patch哈希 → 隔离应用/构建 → 备份数据库、配置及旧产物并验证恢复 → 按账本审阅本次层实际携带的SQL → 执行必要迁移 → 部署Membership及Host → 配置目标代理路由 → 使用不同角色/工作区验收目录、启停、授权回显与保存、导航可见性。

迁移编号需与目标账本核对，不覆盖已执行迁移。核验表所有者、应用数据库角色GRANT及服务间授权。历史清理SQL不是核心自动步骤，应记录拟删除的权限和角色关联并确认无对应功能。WebView扩展还需完整店铺服务及数据库前置表、脚本运行时和窗口宿主。包未执行迁移或部署。

## 回滚

源码按实际应用顺序逆序使用`git apply --reverse --check`及反向应用；共享文件随后被修改时须先审阅差异，不能强行恢复。正式数据库回滚恢复匹配的数据快照和旧服务产物，不能仅反向源码或删除新增列。权限清理和数据转换未提供可凭空恢复被删授权的数据down脚本，执行前必须留存数据库备份。

## 验收边界

- 核心：补丁应用、自动化测试、类型检查和构建已验证；目标数据库迁移及登录用户实机流程未执行。
- 条件扩展：保留实现与依赖，未完成目标组合构建、数据库迁移或桌面验收。
- 最新参考：记录完整近期菜单源码增量；与核心存在重叠，需适配，不能一键混用。
- 开发隧道兼容仅用于未打包、显式SSH模式、数值环回地址及18180端口；正式远程API仍要求HTTPS，不启用任意HTTP例外。
- 不包含配置密钥、Token、Cookie、数据库快照或生产运行日志；不更改现有运行项目。
