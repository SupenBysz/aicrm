# 产品交互设计与项目适配总则

## 1. 设计先回答的问题

每个页面先明确：谁在什么工作区，带着什么目标进入；当前需要什么事实才能决定；主要操作是什么；完成后怎样知道结果；失败或退出后怎样恢复。技术模块、数据库表和接口数量不直接决定用户看到的导航和表单。

设计优先级：任务可完成、事实准确与数据安全 → 信息易理解与状态可感知 → 跨页面一致 → 视觉精致。不能为了首屏漂亮而隐藏错误、把未知统计显示为零、移除用户恢复路径，或额外添加与任务无关的模块。

验收以真实行为为准：看得见、找得到、点得动、结果正确、能够恢复。截图相似或构建成功不能单独证明这五项成立。

## 2. 信息架构与导航

- 按用户任务分组，一项设置只有一个主要维护入口；其他位置引用或跳转，不复制一套配置。品牌图形归品牌信息；版权、备案等法律展示归主体信息；账号个人偏好不混入平台全局默认。
- 分清平台、机构、企业、个人和当前工作区的作用域。页面标题、帮助和保存反馈应让用户知道影响谁；切换工作区后不可短暂展示上一个机构的数据或品牌。
- 全局导航负责功能定位；页面 Tabs 负责同一对象下的平行子任务；表单分组负责字段组织。不要同时堆三层 Tabs 解决简单字段分类。
- 相同功能的菜单、面包屑、页面标题和权限名称使用一致术语。菜单图标来自菜单定义和共享解析器，不在每个页面另猜图标。
- 可见入口必须有真实路由、适当权限及可理解的落点；无权限、功能未接入、暂不可用是三种不同状态。
- 导航的 default、hover、focus、selected、expanded、disabled 状态有清晰区分。hover 提供可见背景反馈；selected 持续表达当前位置，不仅依赖鼠标悬浮或细微颜色变化。
- 顶部工作区/后台大类切换采用已存在的胶囊形态；列表工具栏分段切换采用其紧凑滑槽形态。这是有用途区别的组件变体，不要求所有切换器看起来完全一样，但状态、键盘行为和主题来源要统一。

## 3. 页面骨架与操作层级

典型列表信息顺序：面包屑 → 标题与必要说明/页面主操作 → 页面级概览 → 查询与筛选 → 表格/列表 → 分页。概览是页面事实层，不嵌入表格内部。使用 `ListPageCard.overview` 等既有插槽，不靠额外套 Card 伪造布局。

| 任务 | 默认容器 | 设计理由 |
|---|---|---|
| 查找、比较、批量处理 | 列表页 | 保持查询范围、选择和统计上下文 |
| 编辑一个对象、查看局部详情 | Drawer | 完成后回到原列表位置；遵循固定 Header 规范 |
| 简短确认或局部选择 | Modal | 保持单一决定，不能承载多页复杂表单 |
| 长流程、多阶段内容、需要分享定位 | 独立页面/路由 | 有稳定地址、返回路径和阶段状态 |
| 文档阅读 | 专用阅读页 | 内容可读、版本可定位，不泄露后台编辑能力 |

- 在同一个决策区域突出一个主要动作；页面新增、筛选查询、抽屉保存属于不同区域，可以各有主操作，不机械限制整页只允许一个主色按钮。
- 行操作按常用/低风险优先，危险操作独立表达。更多菜单保留文字含义，不能把用户最常做的动作全部藏起来。
- 相同任务的保存/取消位置一致。Drawer 窗口级操作放固定 Header 右侧，不在底部重复；独立页面表单沿用其既有保存区域，不强制照搬抽屉结构。
- 内容区域限制阅读宽度，但容器仍须响应视口。不能因剩余空间大就等比放大 Logo、表单字号或按钮。
- 页面正文和抽屉正文各有明确滚动容器，避免双滚动争抢。粘性标题、操作栏和窗口控制按钮不得截断边框、遮挡内容或键盘焦点。

## 4. 表单、草稿与保存

- 标签始终可见，placeholder 只给格式示例，不替代标签。选填、必填、长度、单位、格式和作用域应在需要时说明，不用一长段技术解释挤满首屏。
- 字段按用户理解分组；依赖项靠近触发项。隐藏字段应保留兼容值，除非需求明确要求清空；删除输入入口不等于删除数据库字段或已有内容。
- 默认值、继承值、用户覆盖值明确区分。若可继承，显示实际继承来源或有效值；不要只写“默认”让用户猜。
- 品牌、版权等预览来自同一表单草稿；提示“预览”与“已保存”区别，不把未提交草稿误报为当前线上配置。
- 用户输入时采用适度校验，避免每按一个字符就弹错误。提交失败保留全部输入，切换到首个错误所在分组，滚动定位并说明如何修正。
- 保存期间有进行中反馈，防重复提交；失败保留草稿，可重试。配置冲突明确告知“服务器已有更新”，不能静默覆盖或自动清空输入。
- 退出存在未保存内容的页面/抽屉时提供保留或放弃路径；读详情、只改临时查询条件不应反复弹“未保存”。

### 保存模型必须明确

| 模型 | 使用方式 | 必须反馈 |
|---|---|---|
| 显式保存 | 平台配置、品牌、权限等业务设置 | 待保存/保存中/已保存/失败/冲突；关闭前处理草稿 |
| 即时保存 | 已明确约定的个人偏好 | 改动立即生效、自动保存中/已保存/失败；说明关闭不等于撤销 |
| 发布生效 | 协议、模板等版本化内容 | 保存草稿与发布分开；显示当前发布版本、草稿差异和发布结果 |

不能把“保存”“发布”“应用到本人”“设为平台默认”互换用词，也不能为了省按钮把一种保存模型悄悄改成另一种。

## 5. 查询、表格与概览

- 查询条件和统计范围可见，重置恢复已约定默认值并回到第一页。支持 URL 定位的页面维持 URL 与真实查询一致。
- Enter 查询、搜索防抖和查询按钮按现有模式执行；不能因一次重渲染反复发送相同请求。条件变化时后返回的旧请求不得覆盖新结果。
- 表格首先帮助比较：名称与标识稳定靠前，数值和单位一致对齐，状态语义统一，操作列位置稳定。长内容截断时提供完整查看或复制方式。
- 短 ID 只用于展示；复制提供完整 ID，并给出复制成功/失败反馈。不能让视觉省略后的字符串成为业务标识。
- 总数、余额、异常数等概览必须说明范围、时效和统计口径；无权限不泄露数字，统计失败不显示为 0，刷新保留查询上下文。
- “没有任何数据”“筛选无结果”“无权限”“获取失败”分别设计文案和下一步，不统一显示 No data。
- 批量选择是否跨页必须说明；改变查询范围时清除旧选择或按明确策略提示。批处理显示成功/失败条数，保留失败项定位和重试路径，不能只提示“操作完成”。
- 时间注明必要的时区；日期范围的起止边界与后端合同一致。金额、百分比、数量不省略单位，不把展示四舍五入值当作计算输入。

## 6. 反馈、错误与风险操作

- 点击后立即有可感知反馈。首屏未知结构用 Skeleton，已知结构局部更新用局部 loading；后台刷新不必清空整页或把滚动位置拉回顶部。
- 成功反馈对应实际服务器结果。请求超时是结果未知，不能直接假定失败并重复创建、支付、发布或其他可能不幂等的操作。
- 字段错误就近说明；区域错误提供局部重试；整页不可用才使用页面级错误。Toast 不能是长时间错误和重要发布状态的唯一记录。
- 文案包含发生了什么、影响范围、下一步；不给用户堆原始堆栈、内部服务地址或实现细节。排障信息可以在可复制的请求编号中提供。
- 不可逆或高影响操作的确认应包含对象、范围和后果，使用具体动词；可撤销操作优先提供恢复路径，不给每次低风险点击都加确认弹窗。
- 前端隐藏/禁用是交互策略，不替代后端授权。用户根本不可见的敏感能力隐藏；可理解但暂不满足条件的动作可禁用并解释原因，不能暴露未授权详情。

## 7. 视觉层级、主题与组件复用

- 颜色表达角色：背景层次、正文/次要文字、边界、交互、选中、成功、警告、错误。不得按颜色名称写业务判断，也不能只有颜色而无文字/图形表达状态。
- 四套主题及亮暗模式均使用语义 Token；浮层、下拉、Tooltip、空状态、图表、代码块、滚动区域和独立预览同样适配，不能只有外壳换色。
- 初始化首帧应用有效主题；避免先显示旧主题再闪变。独立预览先就绪后展示，不能短暂暴露上一个预览的品牌或配色。
- 统一沿用现有组件的字体、圆角、边框、阴影和控件密度，不在每页用不同 shadow/radius 重新定义组件。布局间距优先现有值；新布局可按 4/8px 节奏提出建议，但未落实为 Token 前不宣称全站已有统一间距系统。
- 字号按内容层级和密度选择，不能通过浏览器缩放、截屏比例或任意 transform 代替布局适配。重要说明不能因次要文字颜色过淡而不可读。
- 图标来自统一图标库、菜单定义或品牌组件；线性/实心及尺寸按用途选择，图标按钮有可访问名称，关键含义不只靠图标猜。
- 品牌、AI 后缀和完整主题缩略图执行[专门规范](../branding/品牌LOGO与AI图标适配规范.md)。关闭 AI 开关后不显示图标属于正确状态，不强制开启。
- 先查[组件索引](../components/README.md)。公共缺口在 Core 或对应组合示例补齐，不让每个插件复制一份相似组件；组件中心示例使用虚构数据，不能连真实服务证明样式。

## 8. 响应式与 Web/桌面一致性

- 按内容与任务决定断点，不根据设备品牌判断布局。参考验收视口为 320/768/1280/1920 CSS px，以及实际客户端最小支持窗口；这是检查样本，不是强制新增的 CSS 断点。
- 宽屏增加有效信息而非放大 Logo 和字号；窄屏允许工具栏换行、次要条件折叠、表单改为单列。关键动作、错误及保存入口仍可达。
- 复杂二维表格可在表格区域横向滚动，避免整个页面横向漂移；必要时保留关键列。不能为了硬塞小屏而把所有列缩到不可读。
- Tabs 过多时采用既有溢出或滚动机制，当前项可见，不靠裁掉标签文字解决问题。
- Electron 与 Web 的业务交互一致；标题栏拖动区、窗口按钮、原生浮层/业务 WebView 是宿主职责，插件不得仿造另一套窗口控制。
- 主 Header 避让使用宿主实际几何信息，不能把某台设备的像素截图硬编码到所有窗口。安装客户端的原生层必须单独验收，浏览器正常不代表客户端正常。

## 9. 可访问性与动效

以 WCAG 2.2 AA 的适用条目作为设计/验收参考，不据此宣称全站已通过合规认证。优先使用原生或 Ant Design 已支持的语义、焦点和键盘行为，不用 div 点击模拟所有控件。

- 普通文本对比度以至少 4.5:1、大文本至少 3:1 为参考；大文本定义及不适用情况按 W3C 原文。Logo 在此条有豁免，但本项目仍要求品牌在亮暗背景清晰可辨，不能把豁免当作看不见也可接受的理由。[W3C 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 指针目标原则上至少 24×24 CSS px；标准允许间距、行内等例外，例外应按实际场景验证。触控高频目标优先采用 44×44 的项目设计建议，不能把 44 冒称为本条 AA 的统一门槛。[W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 焦点可见，顺序符合阅读与任务顺序，不能完全被自定义固定栏遮住。本项目优先保证聚焦控件完整可见；这比该条 AA 的“不可完全遮住”要求更严格。[W3C 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- 键盘可完成查询、Tabs/分段切换、菜单、打开与关闭浮层、保存和错误定位。Modal/Drawer 管理焦点，关闭后返回触发入口；Escape 遵循已有关闭与草稿保护行为。
- 加载、错误、保存结果对辅助技术可感知，避免高频刷新反复打断朗读；禁用原因不能只能通过鼠标 hover 获取。
- 动效只用于解释状态/位置变化；支持减少动态效果偏好，不以持续闪烁吸引注意，不将动画完成作为提交成功的依据。

## 10. 项目适配与渐进治理

适配顺序：核对业务与作用域 → 盘点组件和页面模式 → 映射品牌/Token/配置来源 → 补齐状态和响应式 → 连接真实数据与权限 → 按矩阵验收 → 独立发布并回读。

不得以全局字符串替换代替品牌适配，以全局 CSS 覆盖代替组件状态适配，以删除旧配置代替兼容，以截图相似代替业务验收。派生项目修复必须在其明确授权范围内执行；基座更新不会自动使它们达标。

优先修复数据/权限/误操作风险，再修入口可达、核心流程和状态，再处理间距与装饰差异。记录历史欠账与复用替代关系，避免一次规范完善变成无边界的全站重写。
