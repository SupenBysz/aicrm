# 设计评审与适配交付清单

## 1. 开工前的任务说明

```text
用户/角色/工作区：
要完成的任务与成功判据：
入口、返回位置、可分享地址：
当前具体问题与证据：
本轮改动范围、不涉及的业务范围：
信息分组与主要/次要/危险操作：
数据、权限及默认/继承来源：
保存/生效/发布/退出语义：
复用组件、变体和真实示例路径：
受影响状态、视口、主题、桌面能力：
验证方法与保留的历史限制：
```

简单修改可以用几句话覆盖，不强制生成庞大方案。复杂流程先画任务步骤与状态转换，再设计屏幕；不能从“要加几个卡片”倒推需求。

## 2. 评审检查点

### 产品与信息架构

- 是否解决明确任务，是否增加无关信息/重复设置入口？用户是否知道当前对象、作用域和下一步？
- 概览、筛选、表格、详情职责是否清楚？品牌、主体、个人偏好、全局默认是否混淆？
- 标题、导航、权限与操作名称是否一致？不存在功能是否被伪装为可用入口？

### 交互与数据

- hover/focus/selected/loading/error/disabled 等状态是否可辨？失败、部分成功、超时和冲突如何恢复？
- 保存是否等于发布？关闭是否丢草稿？自动保存是否向用户明确？
- 切换工作区、请求竞争、旧缓存是否可能展示旧数据或错误品牌？前端交互是否仍有后端权限保障？

### 视觉与适配

- 复用的组件/变体是否与用途匹配？是否出现私有复制、写死客户名/色值或近似字体 AI？
- 亮暗及四主题、浮层、独立预览是否同步？窄屏与宽屏是否正确使用空间？
- Logo 是否完整、图标是否遵循开关、字体/间距/圆角/选中反馈是否沿用系统？
- 键盘、焦点、可访问名称及对比度是否检查？桌面宿主能力是否需要单独验证？

## 3. 缺陷优先级

| 级别 | 典型问题 | 交付处理 |
|---|---|---|
| P0 | 越权/泄露旧机构数据、错误公开草稿、误删/重复产生高风险业务结果 | 阻断相关能力发布，先修复和回归 |
| P1 | 核心任务无法完成、保存入口不可达、错误工作区/品牌、必要状态不可读、未保存输入被覆盖 | 阻断受影响任务交付，复验完整相关路径 |
| P2 | 不影响完成任务的间距/对齐/装饰一致性欠账 | 记录明确范围和复现，不扩大成全站重写 |

分级按实际影响，不按问题看起来是否“只是样式”。同一对比度问题可能从 P2 升至 P1；有理由调整级别时写明依据。

## 4. AI 实现/适配的交付约束

- 开始前查设计入口、组件索引和专题规范；在修改说明中列出实际复用路径。没有完全匹配组件时说明差异与归属，不静默复制。
- 不凭截图猜测业务字段、权限或品牌开关，不全局替换合法名称，不用 CSS 掩盖错误数据流。
- 同步 Host 注入、Core 契约、插件调用、组件中心示例/索引和适配文档；按实际改动选择，不为纯文案修改虚构跨模块改动。
- 保留用户未提交代码、现有设置和发布标签。文档补齐不等于历史页面批量整改，更不等于派生项目已同步。
- 不能写“资深设计师已验收”“独立 QA 已通过”，除非该角色确实参与并有可追溯结果。自检应称设计自评或实现自检。
- 本规范不新增统一人工审批门槛。普通可逆实现继续在既有授权范围内完成；真实发布、跨项目修改及不可逆操作仍依据用户授权。

## 5. PR / 交付记录模板

```text
问题与最终行为：
用户任务及影响范围：
复用依据（组件/变体/示例）：
配置/默认/权限/兼容变化：
已验证（源码/测试/本地视觉/线上/安装客户端分别写）：
未验证与剩余限制：
回退或恢复方式（与改动风险相匹配）：
规范/组件中心更新位置：
```

规范变更修改唯一事实源并更新入口；不要在多个文档中复制不同版本的尺寸、状态或发布要求。项目适配完成后，按照[验收矩阵](交互状态与验收矩阵.md)逐项保留结果；缺少必要证据时写“未验证”，不能用“基本一致”代替。
