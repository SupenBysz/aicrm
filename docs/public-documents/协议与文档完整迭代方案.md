# 协议与文档完整迭代方案

日期：2026-10-31
状态：首期已在本地实现并验证，待部署验收。实际范围与边界见[实施与验证记录](实施与验证记录.md)。

## 1. 目标与确认事项

后台提供 Markdown 文档管理，首批承载隐私政策、服务协议，后续通过新建文档扩展注销说明、免责声明等内容，无须为每类文档开发页面。

用户已确认：

- 入口位于“管理中心 → 系统设置 → 系统配置 → 协议与文档”Tab。
- 编辑、预览、草稿、版本发布、历史记录、公开阅读和登录页入口绑定组成完整闭环。
- 前端读取公开文档无需鉴权：不要求登录、Token、Cookie或工作区Header。
- 后台管理仍需认证、平台工作区和对应权限；公开读取与后台管理接口严格分离。
- 保存草稿不改变线上正文；历史发布版本保留可追溯性。

首期仅平台级文档；机构独立协议、多语言、审批流、定时发布、用户同意/重新同意记录后续另行迭代。发布文档不等于用户已同意协议。

## 2. 当前源码依据与集成位置

本次只读检查发现：

- `plugins/ky-system-settings/src/pages/settings-hub-page.tsx`：现有系统配置Tabs、权限筛选、URL tab及仅激活页挂载机制可复用。
- `apps/ky-admin-host/src/pages/login.tsx`：隐私政策、服务条款仍使用固定外部地址，需切换到本项目公开阅读页。
- `services/ky-org-service/internal/server/server.go`：系统配置、平台资料及公开平台资料路由已有归属，文档业务由该服务承载，不新增独立服务。
- `plugins/ky-script-management/package.json`：已有`monaco-editor`和`react-markdown`依赖，可作为技术复用依据；依赖存在不代表已有可直接复用的编辑器组件。
- 后台遵循组件索引、主题Token和固定Header抽屉规范；编辑能力需按需加载，不扩大登录页首屏包。

实施前重新核验当前分支、迁移编号、权限注册、反向代理和真实编辑器调用点，不能仅以本文路径推断实现已存在。

## 3. 产品入口与列表

系统配置新增`documents`Tab，URL沿用现有Tab参数机制；只有拥有文档查看权限的用户可见，直接访问也进行权限校验。无须增加重复侧栏菜单。

列表字段：名称、标识slug、分类、发布状态、草稿状态、当前版本、生效时间、最近更新人/时间、操作。支持名称/slug搜索、分类及状态筛选、分页。

- 分类：协议、隐私、说明、其他；分类只用于管理，不决定公开权限。
- 发布状态：未发布、已发布、已下线。
- 草稿状态独立显示：无未发布修改、有未发布修改。
- 操作按权限显示：编辑、预览、版本记录、复制公开链接、发布、下线。
- 初期不增加概览卡片。列表使用现有ListPageCard及表格规范。
- 首次新建需明确提示“发布后任何人均可访问，请勿填写内部或敏感内容”。

## 4. 编辑与预览

采用宽侧滑窗口，固定Header：左侧文档标题，右侧保存草稿、预览、发布；仅正文滚动，避让主窗口Header。窄屏改为编辑/预览切换。

元信息包含名称、唯一标识、分类、版本说明。新文档slug采用小写字母/数字/连字符，首次发布后冻结，避免公开链接失效。名称可调整。

编辑区支持编辑、双栏、预览三种模式；工具栏提供标题、加粗、列表、引用、链接、表格、代码块。首期使用Markdown源码编辑，不混入富文本双向转换。

- 支持导入UTF-8 `.md`及导出正文；导入先展示确认结果，仅替换草稿，不直接发布。
- 文件扩展名、编码和正文大小由前后端共同检查；建议正文上限1MiB，最终常量及API说明保持一致。
- 保存时发送草稿修订号；冲突返回409，提供重新加载/复制本地内容，不能静默覆盖。
- 离开、关闭抽屉、切Tab时提示未保存修改；关闭确认不误触发布。
- 首期提供显式保存和修改状态，不承诺浏览器崩溃后的本地自动恢复，不在localStorage持久保存正文。
- 发布预览必须使用与公开阅读页相同的渲染器；编辑预览清楚标记“未发布”。
- 编辑器、阅读正文、表格、代码块、链接、弹层及占位背景均跟随主题和亮暗模式，避免初始化闪色。

## 5. 状态、发布与恢复

文档身份、可编辑草稿和不可变发布版本分离。已发布文档可同时拥有修改中的草稿。

首期发布立即生效，生效时间使用服务器事务提交时间，不开放未来时间输入；定时发布另期实现，以免出现前后台生效规则不一致。

发布流程：保存/校验草稿 → 展示版本说明及公开范围 → 用户确认发布 → 服务端事务生成快照并更新当前发布指针 → 刷新公开入口。

- 版本号由服务端按文档递增，如v1、v2；内容摘要使用服务端规范化后的正文计算，不能代替版本主键。
- 发布请求携带期望草稿修订号及幂等标识；重复提交不产生多个版本。超时后按标识查询结果再决定是否重试。
- 发布快照记录标题、正文、版本、版本说明、发布人、发布时间、生效时间、摘要；后续修改名称不改写旧快照。
- 恢复历史版本是复制为新草稿，再发布新版本；不移动旧历史、不删除审计。
- 下线后当前及历史公开正文均不可读取，后台仍保留；重新公开需要明确发布操作，不因保存草稿自动恢复。
- 从未发布且未绑定用途的文档可删除；已发布过的文档仅下线，不提供物理删除入口。
- 已绑定登录用途的文档下线/删除前必须先更换或解除绑定，避免悬空入口。

## 6. 公开阅读与用途绑定

公开页面：`/legal/{slug}`；固定历史版本页：`/legal/{slug}/versions/{version}`。无需登录，直接打开、新标签页、手机及客户端链接均可使用，不经过后台认证守卫或bootstrap。

页面展示发布快照标题、版本、生效日期和正文，可选择历史公开版本。稳定slug页面读取当前版本；历史URL始终对应同一快照。下线后历史URL同样不可读取，不能绕过下线状态。

用途绑定设置两个固定槽位：`privacy_policy`、`terms_of_service`，各选择一份已发布文档。同一文档可按明确选择用于多个槽位；绑定变更需独立权限与审计。新增普通文档不自动增加登录页链接。

登录页先获取公开用途绑定，再展示有效链接；无有效绑定时不展示虚假链接，不继续使用原外部固定地址。不生成或自动发布未经确认的协议正文。

首期可在迁移中建立两份空草稿或由用户新建，但不得将示例内容当正式协议发布。切换现有链接前需完成两份真实内容、发布及绑定验收。

## 7. API合同

以下为拟定合同，实施时纳入项目共享类型与API文档；统一沿用`data/requestId`响应及既有分页格式。

### 7.1 无鉴权接口

| 方法与路径 | 行为 |
|---|---|
| GET `/api/v1/public/documents/{slug}` | 当前已发布、已生效文档快照 |
| GET `/api/v1/public/documents/{slug}/versions/{version}` | 指定公开历史快照，仍检查文档未下线 |
| GET `/api/v1/public/document-links` | 返回两个用途的有效标题、slug、当前版本及相对公开链接 |

- 不依赖Authorization、Cookie、工作区Header；前端使用独立公共请求路径，不触发登录跳转、Token刷新或自动退出。
- 匿名与带登录信息读取同样的公开结果，不因身份额外返回草稿、内部备注、操作者ID或审计数据。
- 不提供匿名管理列表或草稿/内部历史接口；不可访问、未知slug/版本统一404，避免泄漏存在性。
- GET/HEAD具有一致缓存策略；错误响应不缓存。ETag必须纳入发布/下线状态校验之后，不能直接对已下线旧ETag返回304。
- 首期`Cache-Control: public, max-age=0, must-revalidate`，保留ETag，每次重新验证；HTML同样禁止长时间缓存。下线/换绑/发布后不出现长TTL旧内容。
- 无鉴权不等于任意跨域：本项目同源调用优先；外部网站确需调用时配置明确CORS来源，移动/桌面非浏览器调用无需CORS凭据。
- 保留现有请求大小、速率和日志机制，不因公开接口暴露管理能力。

### 7.2 后台管理接口

统一前缀`/api/v1/platform/documents`，必须平台workspace和RBAC。

| 方法与路径 | 行为 |
|---|---|
| GET/POST `/` | 分页列表、新建草稿文档 |
| GET `/{id}` | 管理详情及草稿 |
| PATCH `/{id}/draft` | 携带expectedRevision保存草稿及元信息 |
| POST `/{id}/publish` | 校验修订号、幂等发布 |
| GET `/{id}/versions` | 后台版本列表 |
| GET `/{id}/versions/{version}` | 后台历史正文 |
| POST `/{id}/restore` | 按历史版本生成草稿，检查当前草稿修订号 |
| POST `/{id}/unpublish` | 下线，校验绑定及当前修订 |
| DELETE `/{id}` | 仅删除从未发布且未绑定的文档 |

用途绑定采用独立`GET/PATCH /api/v1/platform/document-links`，PATCH校验绑定修订号及目标已发布状态。404、403、409、正文过大、非法slug、重复slug等使用项目既有错误码风格，响应中不泄露内部SQL。

## 8. 数据与服务边界

拟定由ky-org-service拥有以下领域表，最终表名遵循仓库前缀规则：

| 实体 | 主要内容与约束 |
|---|---|
| document | ID、平台范围、唯一slug、分类、发布状态、当前发布版本指针、修订号、创建/更新时间 |
| document_draft | 文档ID唯一、标题、Markdown、版本说明、草稿修订号、更新人 |
| document_version | 文档ID+版本号唯一、不可变发布快照、摘要、发布人和时间、发布幂等键 |
| document_link_binding | 平台范围+用途唯一、文档ID、修订号、更新人 |

正文存数据库；图片走现有对象存储，不保存base64大图。首期不开放粘贴上传或任意远程图片代理；图片使用已获公开读取权限的资源URL，私有附件不能因文档发布自动公开。

发布、绑定、下线使用事务及必要行锁，防止“校验已发布后并发下线”产生无效绑定；并发发布通过唯一约束和幂等键兜底。跨服务不读写私表，不新增双写者。

迁移编号以执行时最新仓库为准，补齐服务角色GRANT、迁移账本和权限目录。仅由既有单写者迁移流程执行，不让应用启动自动争抢迁移。

## 9. 权限与安全

建议权限：`platform.documents.view/create/update/publish/unpublish/delete/bind`，按项目权限命名规范最终核对；历史查看属于view，恢复草稿属于update。Tab页权限、操作权限、后端校验同步登记，平台超级管理员沿用现有授权机制，不手工绕过。

Markdown禁止原始HTML、脚本、iframe、事件属性、危险URL协议和可执行嵌入；链接仅允许明确协议并设置安全外链属性。渲染策略不能以“后台用户可信”为理由关闭。

公开渲染器按需支持表格等Markdown扩展，编辑器和公开页使用一致插件集。依赖版本、许可证、体积和现有调用点实施时评估，不仅因装有包就直接增加另一套编辑器。

审计记录新建、保存、发布、恢复、下线、删除、绑定变更的主体、对象、版本及结果；常规日志不打印正文、认证凭据或整份请求。内容对比从受权版本读取，不把正文重复塞入审计表。

## 10. 组件复用与工程落点

- 插件承载列表、编辑、版本与绑定业务；Host仅接入公开路由、登录入口和公共请求依赖。
- 优先Ant Design、ListPageCard及项目抽屉布局，已有能力不足再抽出Markdown编辑/阅读组件。
- 文档业务模型不放Core；若编辑/阅读组件确实同时供插件与Host使用，放可独立依赖的共享包，不能让Host反向导入整套业务插件。
- 组件中心增加编辑/只读示例，包含亮暗主题、表格/长链接/代码块、空内容、禁用和加载状态；只用虚构内容，不调用真实文档API。
- 使用懒加载隔离编辑器，公开页不下载后台编辑器、菜单或工作区初始化代码。

## 11. 分期实施与提交

1. 合同与数据：共享类型、数据库迁移/GRANT、权限与审计、管理API及匿名API；先完成隔离测试。
2. 后台管理：Tab、列表、编辑预览、导入导出、冲突提示、历史恢复、发布和绑定。
3. 公开闭环：公开路由、统一阅读器、ETag、匿名请求、登录用途接线及无绑定降级。
4. 标准与回归：组件中心、复用索引、API/运维说明、安全与并发用例、主题及客户端验证。
5. 发布：按固定SHA构建，先迁移再兼容晋级服务与Web，验收真实内容发布/绑定；安装客户端如需发版单独记录。

每期按业务能力分批提交，迁移、实现与验收记录可分别审查；不能将“接口完成”标记为整模块已交付。实施与发布状态以实施记录为准，不将方案确认等同于运行环境已更新。

## 12. 验收清单

- 无Cookie、无Token、无工作区Header的全新浏览器及HTTP请求能读取已发布页面和API；无401、登录跳转或bootstrap依赖。
- 未发布、下线、未知文档及不可公开版本均404；匿名调用管理写接口失败，机构/企业身份不能管理平台文档。
- 保存草稿不改变公开正文/版本/ETag；发布后稳定链接切换新版本，历史链接内容不变。
- 旧ETag在下线后不可获得304；换绑后登录链接更新；正在绑定的文档不能直接下线。
- 双人保存、并发发布/下线/绑定、请求超时重试不丢修改、不生成重复版本。
- 恢复历史只生成草稿；从未发布删除与已发布下线规则生效。
- 脚本HTML、危险链接、超大文件和错误编码不会被执行或绕过校验。
- 编辑/阅读所有主题亮暗一致、无初始闪色；固定Header、窄屏及长内容滚动正常。
- 组件中心真实示例、源码复制及索引一致；公开页不加载编辑器与后台鉴权流程。
- 登录页两份真实协议发布并绑定后完成匿名点击验收；无真实正文时不得用示例替代验收。
- 自动化检查、Web浏览器、安装客户端分别记录证据，构建成功不等于现场交互通过。

## 13. 部署与回退

使用现有准生产测试环境及集中构建链路。部署前记录固定源码SHA、镜像摘要、迁移账本、当前运行版本，并取得匹配数据库备份与恢复证据。

迁移采用新增表/权限的兼容策略，旧应用可继续运行。回退通常先退服务/Web、保留新增文档数据；不以删除版本表作为常规回退。若涉及数据恢复，必须明确备份时间、恢复范围及期间新发布数据的处理，镜像回退不能替代数据库恢复。

Nginx/网关需同时覆盖公开API与`/legal/*`页面，不能被登录重定向或受权workspace代理拦截。检查CSP、缓存、缺失资源404、健康探针以及匿名外部访问。公开功能不得依赖服务器本地Markdown文件或构建时嵌入的固定正文。

## 14. 实施前锁定项

无需新增用户决策即可按本方案推进：首期平台级、立即发布、Markdown源码编辑、系统配置Tab、公开匿名读取、受权后台管理。具体迁移编号、组件归属、接口错误码和依赖版本由实现时源码核验确定并记录。

待内容就绪后确认的运营事项：两份真实协议正文、首次发布及用途绑定对象。机构覆盖、多语言、定时发布和同意记录不隐含纳入本期。
