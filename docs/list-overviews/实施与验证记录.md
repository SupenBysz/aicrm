## 2. 指标事实及查询一致性

- Org的机构、企业、资质列表和summary复用各自conditions函数；平台与机构企业接口分开，机构agencyScope不可被请求覆盖。
- Membership成员复用原列表conditions与ResolveMemberScope；邀请列表和summary共用可见邀请人解析及基础条件，保留nil=不限制、空集合=无可见记录的区别。
- Matrix列表与summary复用账号条件，待处理为正常账号且expired/verify_required/risk/unknown；停用账号不重复计入待处理。未登录/登录中未列为故障。
- Auth新旧列表和summary共用LoginLogFilter/条件构造器；summary忽略result，保留账号、userId及时间交集。失败账号保留大小写，排除空账号，不使用userId合并未注册账号。
- 每个概览单次SQL返回全部指标，使用最多3秒的查询上下文；计数校验非负及JavaScript安全整数范围。SQL表/字段/状态表达式由服务静态定义，用户值全部参数化。
- 不返回账号、用户或业务记录的额外集合；统计权限与当前列表一致，没有新增“全局统计”权限或跨服务私表查询。
- 单独请求的列表与概览不宣称强事务快照；邀请到期时点采用服务端asOf，手动刷新可更新边界。

## 3. 新接口和参数合同

全部沿用Authorization与workspace Header、标准data/error/requestId封装。

| 路径 | 权限/范围 |
| --- | --- |
| GET /api/v1/platform/agencies/summary | platform.agencies.view，平台原列表范围 |
| GET /api/v1/platform/enterprises/summary | platform.enterprises.view，keyword与agencyId |
| GET /api/v1/agency/enterprises/summary | agency.enterprises.view，强制当前agencyScope，不新增菜单/页面 |
| GET /api/v1/platform/qualifications/summary | platform.qualifications.view，平台审核列表 |
| GET /api/v1/workspace/members/summary | 对应workspace members.view及成员ScopeFilter |
| GET /api/v1/invitations/summary | 对应workspace invitations.view及可见邀请人集合 |
| GET /api/v1/matrix-accounts/summary | 对应workspace matrix_accounts.view，当前workspace及平台 |
| GET /api/v1/login-logs/summary | platform.login_logs.view，平台认证日志范围 |

概览schemaVersion=1，返回total、metrics、asOf、scope。scope说明基础搜索范围和ignoredFilters，不接收分页/排序/未知参数，多值参数或非法状态返回400；允许有界中文关键词。失败返回503 statistics_unavailable，无权限返回403，不伪装为0。

### 新筛选的兼容

1. 邀请原status字段和原status过滤不变；新增effectiveStatus参数和投影。status与effectiveStatus同时出现（包括空值占位）返回400。读取不UPDATE邀请，accepted/cancelled等终态不被时间覆盖。
2. Matrix新增attention=required，与status/loginStatus互斥；原登录状态筛选额外接受类型合同中已有unknown。summary不按这三项状态过滤。
3. 日志原endAt仍为包含结束边界，未提供新参数的旧调用不被新增31天限制截断。新summary必须提供startAt和endBefore；使用endBefore的新列表也必须提供合法startAt，范围大于0且不超过31天。新旧结束参数不能同时提供。
4. 新账号参数account去首尾空格后精确匹配，不转小写；与userId取交集。新前端默认最近24小时，绝对时间展示/输入明确为北京时间。
5. 新日志输入控件按秒展示；没有修改时间字段、只修改账号时保留原URL时间及毫秒精度。翻页/点击卡片不滑动窗口；相对24小时手动刷新会重算窗口。
6. 相关列表响应有filterVersion=1。客户端在effectiveStatus/attention/endBefore有效使用时检查此标记；缺失则报升级提示，不展示未经确认的列表结果。独立summary暂不可用时仍可使用已确认合同的明细。

## 5. 实施中发现并处理的问题

- 原schema允许组织pending、成员invited/left；这些是合法状态，独立返回并说明，不当作未知错误或藏进正常状态。
- 旧后端可能忽略新筛选参数；仅凭summary存在或HTTP 200不足以确认明细筛选生效，增加明细filterVersion检查，避免扩大结果展示。
- 新旧时间结束边界不能混用，保留原endAt、增加endBefore；界面未编辑时间时不能损失URL的毫秒精度。
- 错误或撤权时不仅主计数，辅助计数描述也不能展示旧值；公共组件在无可用数据时隐藏依赖数据的说明。
- 中文搜索长度按合法UTF-8字符检查，避免把200个汉字按600字节误拒绝。
- 初次HTTP测试夹具遗漏当前ky_membership_role的workspace字段约束，已修正夹具并重跑；未修改业务schema绕过约束。组合UI测试曾对含React所有者引用的快照做JSON序列化，已改为渲染节点断言；最终相关测试通过。
